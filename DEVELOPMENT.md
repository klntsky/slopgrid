# Development

## Requirements and setup

Use Node.js 22.12 or newer, pnpm 12.4.2, and tmux. Supply `GITHUB_CLIENT_ID` and `GITHUB_CLIENT_SECRET` through private runtime configuration before starting the app; either missing or empty variable prevents startup. SQLite uses `better-sqlite3`; environments without a matching prebuilt binary need Python and a C/C++ build toolchain. Native build permissions are in `pnpm-workspace.yaml`.

```sh
pnpm install
pnpm exec playwright install chromium
pnpm dev
```

Open http://localhost:3000. Chromium resolves HTML output hosts ending in `.localhost` to loopback. Images, Markdown, and SVG use paths on the application origin. OpenRouter OAuth supports localhost callbacks. The development server creates a SQLite database and encryption key under `.data/`; preserve both to retain sessions. Manual API keys are entered through the shared connection control and saved only in browser localStorage. OAuth credentials retain their existing encrypted server-side storage.

## GitHub integration verification

`pnpm test:e2e:github` runs against real GitHub and OpenRouter. Supply GitHub client credentials and the normal real OpenRouter test credential source. Set `GITHUB_INTERACTIVE=1` to complete GitHub login and any two-factor challenge in a visible browser, or provide `GITHUB_BROWSER_STATE` referencing a private Playwright storage-state file containing an authenticated GitHub browser session. Keep this file outside the repository. Register the callback using the test application origin followed by `/api/auth/github/callback`. The runner rejects an occupied test port before launching.

The test creates and generates an anonymous grid, signs in through GitHub, verifies claiming and publication attribution, signs in through GitHub in a separate browser context, checks account access and billing, and signs out. It uses no mocked OAuth or inference endpoints. Missing credentials, authorization failure, and provider errors fail verification rather than silently skipping it. Unit identity tests exercise the real app and database without exchanging OAuth codes; their route-only client credentials do not authenticate with GitHub.

## Interface text

Never editorialize user-facing text. When creating new UX surfaces, summarize the user-facing text in the conversation so the user can review it.

## Validation

```sh
pnpm test
pnpm test:unit
pnpm test:e2e:mock
pnpm test:e2e:real
```

`pnpm test` runs unit tests and both Playwright projects. `test:e2e` builds once and runs the mock and real suites sequentially. The separate E2E commands build and run their respective project. Each app server runs in a uniquely named window in tmux session `bg`, using temporary SQLite, outputs, and test artifacts outside the checkout, which are removed after the run.

The mock project exercises the real app and AI SDK against a local HTTP OpenRouter fixture. It covers OAuth with PKCE, manual connection and invalid-key replacement, image rendering, controlled billing and provider failures, retries, publishing, ownership, isolated hosting, layout, streaming stages, fair scheduling, and HTTP cancellation. It never contacts OpenRouter or spends credits.

The real project uses OpenRouter directly for one-cell Markdown, SVG, and static website generations, including rendering and reload. These success scenarios replace their mocked equivalents. It selects `cohere/north-mini-code:free`, disables thinking, and uses a $0.001 cell budget. There is no paid-model fallback, retry of failed tests, or silent skip when credentials or the model are unavailable. Real-test traces, screenshots, and videos are disabled.

Provide `OPENROUTER_API_KEY` to the test process, or create `slopgrid/test.config.json` under your user configuration directory (`XDG_CONFIG_HOME`, otherwise `~/.config`) with `keySource` pointing to an existing environment file and optional `keyVariable` (default `OPENROUTER_API_KEY`). The configuration contains a reference rather than a copied credential. The runner supplies the resolved key only to Playwright; the browser connects through the normal manual-key form. Keep credentials and this private configuration outside the repository.

Tests focus on user outcomes and consequential boundaries rather than implementation snapshots. Controlled error responses, exact billing amounts, timing gates, and scheduling scenarios remain mocked because their outcomes must be reproducible.

## Runtime configuration

`pnpm build` checks TypeScript and creates the frontend build. `pnpm start` serves that build in production mode. The production process requires `APP_ORIGIN`, `OUTPUT_DOMAIN`, and `KEY_ENCRYPTION_SECRET` to be provided in its environment.

| Variable                | Behavior                                                                                                                                                          |
| ----------------------- | ----------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `APP_ORIGIN`            | Application origin, including scheme and optional port; HTTPS is required in production.                                                                          |
| `OUTPUT_DOMAIN`         | HTML output host suffix beginning with a hyphen, with an optional port; joins the cell ID in one DNS label. Images, Markdown, and SVG use the application origin. |
| `KEY_ENCRYPTION_SECRET` | Exactly 64 hexadecimal characters representing the persistent 32-byte encryption key. Required in production.                                                     |
| `DATABASE_PATH`         | SQLite file path; defaults to `.data/slopgrid.sqlite`. Its parent directory must exist.                                                                           |
| `OUTPUTS_PATH`          | Directory for generated output files; defaults to an `outputs` directory beside the SQLite database.                                                              |
| `PORT`                  | Listening port; defaults to 3000.                                                                                                                                 |
| `BIND_ADDRESS`          | Listening address; defaults to `127.0.0.1`.                                                                                                                       |
| `WORKERS_MAX`           | Maximum concurrent cell generations across the application process; defaults to 100 and must be a positive safe integer.                                          |

Development creates a local encryption key automatically. Changing the encryption key makes existing stored credentials unreadable. Run one application process per database: workers and SSE subscribers are process-local.

## Storage and migrations

SQLite stores grid configuration, cell state, encrypted OpenRouter session credentials, users, and provider identities. Migration 8 adds users and identities keyed by provider and provider subject. GitHub access tokens are used only for profile retrieval and are not persisted. Generated output bodies live on disk, with one directory per cell; image files contain binary bytes and website files retain their relative paths. Streaming drafts remain in memory. Changing metadata or publishing a grid never rewrites its completed output files.

Append schema changes to the SQL migration list in `server/migrations.ts`, using a positive integer version greater than every previous version. Do not reorder or edit applied migrations. Startup validates the full sequence, applies only pending versions, and records each version through SQLite’s `user_version` in the same transaction as its SQL. A failed step rolls back its SQL and version, while earlier successful steps remain applied. A database with an unsupported or newer version cannot start. Tests cover migration ordering, reruns, data preservation, and rollback.

The current schema starts with version 1 on an empty database and does not import the previous unversioned schema. Migration 3 removes the obsolete harness setting from saved grid inputs. SQLite backups and generated file backups must be kept together, along with the encryption key needed to read stored credentials. Temporary output directories can remain after a process crash; an unfinished cell stays retryable, and retry replaces any uncommitted output for that cell. Completed outputs are not automatically removed; temporary website previews are cleared at startup and when an attempt ends.

## Operational limits

Each browser session can create ten grids and retry thirty times per hour; each client IP can create thirty grids per hour. API traffic is limited to 600 requests per client IP per minute, and generated outputs to 2,000 requests per client IP per minute, with 20,000 requests per minute for website preview paths to support repeated bundle refreshes. Creation and Resume check the authenticated OpenRouter credit balance before starting inference. A balance below $3 returns a `LOW_BALANCE` response without creating or starting work; explicit continuation stores a concurrency limit of one in the browser session. For all balances, each start/resume check stores `max(1, floor(balanceUsd / 3))` as the session concurrency limit. The limit applies across that session’s grids and remains subject to the shared `WORKERS_MAX` cap. Balance lookup failures prevent new inference and surface an error. Existing in-flight calls are allowed to finish when the limit changes. Grids queue their cells in a shared worker pool, with up to `WORKERS_MAX` concurrent cell generations. Allocation counts all active cells across each browser session’s grids. Each free slot goes to an eligible session with the fewest workers; ties favor the least recently allocated session, with unserved sessions first. All available capacity is used, with no reserved slots or cancellation for rebalancing. Manual pause aborts active requests for that grid and removes its queued work until resume. Billing or authentication failures pause queued work for that session, while its already active calls can finish. A worker slot covers the whole cell, with one model call per attempt. SSE is limited to five connections per session and 100 globally; the client keeps a connection only while the grid can change through active or queued generation, closing it when stable and reopening it after resume. These counters are in memory and reset on restart. OpenRouter requests have no application deadlines or HTTP client connection, header, or body timeouts. Manual pause still aborts inference, and SDK automatic retries are disabled. The scheduler retries HTTP 429 and HTTP 402 errors identified as transient in-flight budget exhaustion, with up to five retries per cell. Delays start at one second, double after each failure, include up to 50% jitter, and honor longer Retry-After values given as seconds or an HTTP date. A cooldown applies across the browser session’s grids; waiting cells release worker slots, and existing requests can finish. Retry counts and cooldowns are process-local. Manual pause stops queued retries, while Resume still honors an unexpired cooldown. Genuine credit or key limits retain the billing interruption flow. Each automatic retry restarts the whole unfinished cell, with a new model call; completed cells are never retried. Provider messages and codes are persisted in cell metadata and returned to the client, without raw request bodies or response headers. Streaming drafts remain in memory and are broadcast at most once per 300 ms per grid, with cell transitions persisted and emitted immediately.

Generation has no application output-byte or bundle-file-count limit. Grid creation requires a positive `budgetUsd` setting; the form starts at $5 per cell attempt. Text generation always resolves catalog pricing and computes a token ceiling before calling the provider. Migration 4 fills missing budgets on existing grid inputs with $5. Catalog discovery retains USD/token input and output rates, per-request charges, context length, and the advertised completion ceiling. `server/generation-budget.ts` reserves an input estimate of UTF-8 prompt/system bytes plus 256 tokens of message overhead, then divides the remaining dollars by the output-token price and floors the result. The output limit also respects the advertised model completion ceiling and remaining context. Free output uses that model ceiling. Missing pricing or context information fails the cell before an inference call. The provider route is constrained to those prompt/completion rates through `provider.max_price` in USD per million tokens. Each cell makes one model call using the full allowance. Each text request sends an explicit `max_tokens` through the SDK’s `maxOutputTokens`; reasoning and visible output share it. Input tokenization, provider overhead, and billing variations make this an estimated monetary ceiling. Retries receive a fresh allowance, while completed cells keep their previous outputs. Image generation uses the dedicated image API without this text-token budget. Finish reasons and reasoning-token counts are stored exclusively in the billing ledger and omitted from grid snapshots. Migration 5 removes redundant completion arrays from cells that have ledger records. Migration 6 drops the attempt-group column; cell usage comes directly from the latest call, while billing retains all historical calls. Only `stop` is accepted as successful text completion; other reasons fail the cell with a generic error while retaining reported usage and cost. Images retain the reported finish reason when available, otherwise successful image generation establishes completion. Finish metadata and per-call usage are persisted in the inference ledger, with cell usage derived from its latest call; finish reasons are omitted from billing responses and have no UI display. The private billing API returns 50 calls per page and totals all reported charges, including earlier retries. Entries are created at inference dispatch, retain errors and cancellations, and are marked interrupted by explicit startup recovery if the process ended before completion. Earlier requests are not backfilled, and missing provider charges remain unknown. SVG output is stored without markup validation after trimming whitespace and optional Markdown fences; incomplete or unconventional SVG does not fail generation. Website bundles must contain `index.html`, safe relative paths with html/css/js/json/txt/svg/md extensions. Models and their reasoning capabilities are discovered from OpenRouter and cached for five minutes. The form warns about incompatible output formats, mandatory reasoning disabled through None, unsupported effort levels, and explicit efforts whose router capabilities are unpublished. Model default leaves reasoning settings to the model, and minimal is available alongside the other gateway effort levels. These warnings are advisory: creation, retries, and provider calls send the selected settings without requiring catalog approval. Structural input validation and the requirement to use enabled prompt variables still apply. Provider availability and restrictions that are not published in metadata can still cause retryable generation failures. No automatic data retention or database cleanup runs. Sessions expire 30 days after creation. Treat output URLs as bearer capabilities, including before publication.

## Icons

Interface icons use `lucide-react`, under the [Lucide ISC license](https://lucide.dev/license), with MIT notices for icons derived from Feather. The distributed notices are included in `public/lucide-LICENSE.txt` and copied into the build. The project mark is the custom 5×5 cell SVG in `public/slopgrid.svg`, shared by the wordmark and favicon. The OpenRouter connector uses its official brand asset. The GitHub sign-in button uses the unmodified white Invertocat SVG from [GitHub’s logo assets](https://brand.github.com/foundations/logo).

Markdown rendering uses the shared React component with `react-markdown` and `remark-gfm`, with no raw HTML parser plugin. The output route serves the stored Markdown source for `?raw=1` and uses React server rendering for direct pages. Vite aliases `decode-named-character-reference` to its default lookup-table implementation because its browser implementation uses an innerHTML assignment.

## Publishing and listings

Grid visibility uses `private`, `unlisted`, and `public`, while `published` retains the generation lock. `POST /api/grids/:id/publish` accepts `{ visibility }`; a bodyless request publishes as unlisted for compatibility. An already published grid accepts its existing visibility, and its owner can promote an unlisted grid to public visibility. `GET /api/grids/public` returns public summaries without ownership or cell data, newest first. Both summary APIs include output format and visibility. Migration 7 assigns existing published grids to unlisted and other grids to private. The publish dialog remembers confirmation suppression under `slopgrid-skip-publish-confirmation` in local storage after successful confirmation. Listing format icons use Tippy on hover and keyboard focus. Publishing tests cover access, immutable visibility, summary filtering, and migration; browser tests cover the dialogs, preferences, and tooltips.
