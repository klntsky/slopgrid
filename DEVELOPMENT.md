# Development

## Requirements and setup

Use Node.js 22.12 or newer, pnpm 12.4.2, and tmux. The same-site HTTPS browser test uses OpenSSL to generate a temporary test certificate. Supply `GITHUB_CLIENT_ID` and `GITHUB_CLIENT_SECRET` through private runtime configuration before starting the app; either missing or empty variable prevents startup. SQLite uses `better-sqlite3`; environments without a matching prebuilt binary need Python and a C/C++ build toolchain. Native build permissions are in `pnpm-workspace.yaml`.

```sh
pnpm install
pnpm exec playwright install chromium
pnpm dev:engine
# In another terminal:
pnpm dev
```

Open http://localhost:3000. Chromium resolves HTML output hosts ending in `.localhost` to loopback. Images, Markdown, and SVG use paths on the application origin. OpenRouter OAuth supports localhost callbacks. The development server creates a SQLite database and encryption key under `.data/`; preserve both to retain sessions. Manual API keys are entered through the shared connection control and saved only in browser localStorage. OAuth credentials retain their existing encrypted server-side storage.

## GitHub integration verification

`pnpm test:e2e:github` runs against real GitHub and OpenRouter. Supply GitHub client credentials and the normal real OpenRouter test credential source. Set `GITHUB_INTERACTIVE=1` to complete GitHub login and any two-factor challenge in a visible browser, or provide `GITHUB_BROWSER_STATE` referencing a private Playwright storage-state file containing an authenticated GitHub browser session. Keep this file outside the repository. Register the callback using the test application origin followed by `/api/auth/github/callback`. The runner rejects an occupied test port before launching.

The test creates and generates an anonymous grid, signs in through GitHub, verifies claiming and publication attribution, signs in through GitHub in a separate browser context, checks account access and billing, and signs out. It uses no mocked OAuth or inference endpoints. Missing credentials, authorization failure, and provider errors fail verification rather than silently skipping it. Unit identity tests exercise the real app and database with mocked GitHub token and profile responses, including claiming active grids, session rotation, and callback replay rejection. They do not authenticate with GitHub.

## Frontend builds

The Markdown renderer is included directly in the main browser bundle, so opening a Markdown preview does not request a separate renderer chunk. Vite retains previous files in `dist` during rebuilds so open pages can still fetch assets from their original build. The frontend router serves HTML with `Cache-Control: no-store`, hashed assets with immutable caching, and missing assets with `no-store` to avoid caching a temporary 404.

## Validation

### Test design

1. Use pnpm and Playwright, with real-provider browser suites separate but enabled in the default full run. Exercise the normal manual-key flow with a cheap or free model and cover structured website streaming with an explicitly selected capable model.
2. Assertions enforce complex behavioral properties: state transitions, persistence, ownership, recovery, and component interactions. Exclude trivial assertions, constant checks, CSS appearance tests, and checks that merely mirror implementation.
3. Group independent browser scenarios with isolated fixture state and unused ports for parallel execution. Reuse generated grids for related read-only checks while keeping mutation scenarios isolated.
4. Share integration-test resource setup and teardown through a small fixture, keeping scenarios and assertions explicit. Test servers must use the real frontend-serving implementation so routing and cache behavior are exercised.
5. Verify the GitHub OAuth integration through its real flow. Use controlled inference streams for deterministic scheduling, failure, billing, and ordering scenarios while retaining the real provider adapter/parser, database, files, engine, web process, internal API, and browser.
6. Use explicit synchronization points, and keep crash controls confined to test processes. An upstream inference HTTP fixture supplies model responses; application generation APIs remain real.

### Running the suites

```sh
pnpm test
pnpm test:built
pnpm test:unit
pnpm test:e2e:mock
pnpm test:e2e:real
```

`pnpm test` runs unit tests, builds once, and runs the mock and real Playwright projects. `pnpm test:built` runs the same suites against the existing build, without rebuilding it. The E2E runner also accepts `--reuse-build` for focused runs against an existing build. The separate E2E commands build once and run their respective project.

Mock E2E tests are grouped into setup, display, access, and generation files and run with three workers. Each worker has its own app, upstream fixture, unused ports, temporary SQLite database, outputs, and tmux window in session `bg`; state-changing tests remain sequential within each file. Shared helpers keep setup consistent, and interaction journeys reuse grids across state transitions and reloads. Real-provider and GitHub suites run serially in one isolated app server each. Temporary app data and test artifacts are removed after each worker or suite finishes.

The mock project exercises the real app and AI SDK against a local HTTP OpenRouter fixture. It covers OAuth with PKCE, manual connection and invalid-key replacement, image rendering, controlled billing and provider failures, retries, publishing, ownership, isolated hosting, streaming stages, fair scheduling, and HTTP cancellation. It never contacts OpenRouter or spends credits.

The real project uses OpenRouter directly for one-cell Markdown, SVG, and static website generations, including rendering and reload. These success scenarios replace their mocked equivalents. It selects `nvidia/nemotron-3-super-120b-a12b:free`, disables thinking, and uses a $0.001 cell budget. There is no paid-model fallback, retry of failed tests, or silent skip when credentials or the model are unavailable. The website request specifies exact HTML, CSS, and JavaScript contents so this integration check tests transport, storage, and browser execution without depending on the model's design choices. Real-test traces, screenshots, and videos are disabled.

Provide `OPENROUTER_API_KEY` to the test process, or create `slopgrid/test.config.json` under your user configuration directory (`XDG_CONFIG_HOME`, otherwise `~/.config`) with `keySource` pointing to an existing environment file and optional `keyVariable` (default `OPENROUTER_API_KEY`). The configuration contains a reference rather than a copied credential. The runner supplies the resolved key only to Playwright; the browser connects through the normal manual-key form. Keep credentials and this private configuration outside the repository.

Mouse-drag browser scenarios cover two-axis panning from image padding and cell footers, exclusion of image/Markdown/website content and controls, pointer release, and coexistence with column resizing. Touch gestures retain checks that zooming and scrolling respond to interaction, and keyboard resizing is checked through saved dimensions and restored handle values. Controlled error responses, exact billing amounts, timing gates, and scheduling scenarios remain mocked because their outcomes must be reproducible.

The runtime behavior tests share `tests/runtime-fixture.ts`: a controlled OpenRouter HTTP service, a real inference child, a replaceable web child, and a temporary SQLite database and output directory. The actual provider SDK, stream parser, billing recorder, and Unix-socket API remain in use. Tests explicitly release streaming chunks or failures instead of relying on provider response timing. Sessions are seeded directly; authentication flows have separate coverage.

Grid-price coverage distinguishes visible successful-output cost from owner-only lifetime spending. Billing tests cover reported usage arriving before cell settlement, reported zero charges, cancellation, retries, and isolation between grids. Browser coverage follows both totals through streaming, failure, retry, reload, and publication; HTTP and SSE coverage ensures non-owners never receive `spentUsd`. Reordered-snapshot coverage checks both displayed totals. A controlled-stream browser scenario checks thinking scroll-following through successive chunks and viewport resizing, wheel-scrolling up to preserve a reading position, returning to the bottom, and completion through the saved-trace fetch. Thinking-exhaustion coverage distinguishes a fully consumed reasoning budget from partial output and early termination, verifies durable errors and traces, separates charges from successful-output costs, and observes SSE closure. SVG view-switch coverage checks decoded image content while hidden behind thinking, preserves the mounted preview across toggles, and verifies completion while thinking remains selected. Expansion coverage follows SVG updates through completion in the overlay and checks image/SVG collapse via Escape, restored focus, retained table elements, and saved dimensions.

### Required runtime coverage

1. **Web replacement during generation:** keep a real browser open while Markdown, thinking, and website assets stream; replace the web process and verify reconnection, continued previews, correct final content and prices, and no extra provider calls. See `tests/e2e/runtime.spec.ts`.
2. **Lost acknowledgements and competing starts:** lose the response after the engine accepts Start, retry through a replacement web process, and race multiple starts; each cell must run only once. See `tests/generation-commands.test.ts`.
3. **Concurrent writes:** interleave title edits, ownership claims, generation completion, publication, and retries across processes; preserve both metadata and generation changes and prevent publication while work is active. See `tests/generation-metadata.test.ts`.
4. **Complete draining:** cover queued cells, retry timers, and cancelled calls whose provider work has not settled. Accepted work finishes, new work is rejected, drained status waits correctly, and cancelling maintenance restores admission. See `tests/generation-drain.test.ts`.
5. **Engine death at persistence boundaries:** kill the real process midstream and around billing, file, and cell-state persistence. Preserve committed outputs, retain recorded charges, settle interrupted ledger entries, and require explicit Resume without duplicating completed work. See `tests/generation-crash.test.ts`.
6. **Reordered browser updates:** release older HTTP or SSE snapshots after newer state, including across reconnection, and ensure output, thinking, title, status, and prices never regress even transiently. See `tests/e2e/ordering.spec.ts`.
7. **Slow and disconnected viewers:** stall one subscriber while another remains healthy, repeatedly disconnect/reconnect, and verify generation continues, abandoned capacity is released, and a reconnect sees current state. See `tests/generation-viewers.test.ts`.

Crash tests use `tests/crash-checkpoint.ts` to attach Node's inspector to the fixture engine and stop at a specific statement before killing the process. Checkpoints are located in the executed script and must identify a unique statement. Inspector activation exists only in the test child entry point. The abort-ignoring cancellation case reuses the scheduler's `ControlledProvider` because an HTTP client settles locally when its request is aborted, even if the remote server keeps working.

## Runtime configuration

`pnpm build` checks TypeScript and creates the frontend build. `pnpm start` serves that build in production mode and connects to the separately managed inference process started with `pnpm start:engine`. The production process requires `APP_ORIGIN`, `OUTPUT_DOMAIN`, and `KEY_ENCRYPTION_SECRET` to be provided in its environment.

| Variable                | Behavior                                                                                                                                                          |
| ----------------------- | ----------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `APP_ORIGIN`            | Application origin, including scheme and optional port; HTTPS is required in production.                                                                          |
| `OUTPUT_DOMAIN`         | HTML output host suffix beginning with a hyphen, with an optional port; joins the cell ID in one DNS label. Images, Markdown, and SVG use the application origin. |
| `KEY_ENCRYPTION_SECRET` | Exactly 64 hexadecimal characters representing the persistent 32-byte encryption key. Required in production.                                                     |
| `DATABASE_PATH`         | SQLite file path; defaults to `.data/slopgrid.sqlite`. Its parent directory must exist.                                                                           |
| `OUTPUTS_PATH`          | Directory for generated output files; defaults to an `outputs` directory beside the SQLite database.                                                              |
| `PORT`                  | Listening port; defaults to 3000.                                                                                                                                 |
| `BIND_ADDRESS`          | Listening address; defaults to `127.0.0.1`.                                                                                                                       |
| `GENERATION_SOCKET`     | Private Unix socket shared by web and inference processes; defaults to `generation.sock` beside the database.                                                     |
| `GENERATION_DRAINING`   | Set to `1` to start the inference process with admission closed.                                                                                                  |
| `FRONTEND_PATH`         | Frontend build directory served by the web process; defaults to `dist`.                                                                                           |
| `OPENROUTER_BASE_URL`   | Provider API base URL for both processes; defaults to the OpenRouter API.                                                                                         |
| `WORKERS_MAX`           | Maximum concurrent cell generations across the inference process; defaults to 100 and must be a positive safe integer.                                            |

Development creates a local encryption key automatically. Changing the encryption key makes existing stored credentials unreadable. Run exactly one inference process per database. The web process connects through the configured generation socket and can restart independently. Both processes must use the same database, output directory, and encryption key.

## Storage

SQLite stores grid configuration, cell state, encrypted OpenRouter session credentials, users, and provider identities. Provider identities are keyed by provider and provider subject. GitHub access tokens are used only for profile retrieval and are not persisted. Generated output bodies live on disk, with one directory per cell; image files contain binary bytes and website files retain their relative paths. Streaming drafts remain in memory. Changing metadata or publishing a grid never rewrites its completed output files.

`server/database.ts` defines the current schema. Startup creates it atomically for an empty database and accepts existing databases only at the current SQLite `user_version`. Historical migrations and data conversions are not supported. Storage and route tests exercise persistence and reopening; unsupported-version tests check that rejection preserves existing data.

SQLite backups and generated file backups must be kept together, along with the encryption key needed to read stored credentials. Temporary output directories can remain after a process crash; an unfinished cell stays retryable, and retry replaces any uncommitted output for that cell. Completed outputs are not automatically removed; temporary website previews are cleared at inference-process startup and when an attempt ends.

## Operational limits

Each browser session can create ten grids and retry thirty times per hour; each client IP can create thirty grids per hour. API traffic is limited to 600 requests per client IP per minute, and generated outputs to 2,000 requests per client IP per minute, with 20,000 requests per minute for website preview paths to support repeated bundle refreshes. Creation and Resume check the authenticated OpenRouter credit balance before starting inference. A balance below $3 returns a `LOW_BALANCE` response without creating or starting work; explicit continuation permits the requested parallelism. `GET /api/inference-capacity` returns the authenticated balance and recommended count `max(1, floor(balanceUsd / 3))`, or one when manual-key credits are unavailable; responses are uncached and limited to 60 checks per session per minute. Creation accepts an optional integer `parallelWorkers` from 1 to 64 and saves it with the grid. Each start/resume check stores this requested count, or the automatic recommendation when omitted, as the session concurrency limit. Each grid also respects its own requested count, so another grid raising the session limit cannot exceed that request. The session limit applies across its grids and remains subject to the shared `WORKERS_MAX` cap. Balance lookup failures prevent new inference and surface an error. Existing in-flight calls are allowed to finish when the limit changes. Grids queue their cells in a shared worker pool, with up to `WORKERS_MAX` concurrent cell generations. Allocation counts all active cells across each browser session's grids. Each free slot goes to an eligible session with the fewest workers; ties favor the least recently allocated session, with unserved sessions first. All available capacity is used, with no reserved slots or cancellation for rebalancing. Manual pause aborts active requests for that grid and removes its queued work until resume. Billing or authentication failures pause queued work for that session, while its already active calls can finish. A worker slot covers the whole cell, with one model call per attempt. SSE is limited to five connections per session and 100 globally; the client keeps a connection only while the grid can change through active or queued generation, closing it when stable and reopening it after resume. These counters are in memory and reset on restart. OpenRouter requests have no application deadlines or HTTP client connection, header, or body timeouts. Manual pause still aborts inference, and SDK automatic retries are disabled. The scheduler retries HTTP 429 and HTTP 402 errors identified as transient in-flight budget exhaustion, with up to five retries per cell. Delays start at one second, double after each failure, include up to 50% jitter, and honor longer Retry-After values given as seconds or an HTTP date. A cooldown applies across the browser session's grids; waiting cells release worker slots, and existing requests can finish. Retry counts and cooldowns are process-local. Manual pause stops queued retries, while Resume still honors an unexpired cooldown. Genuine credit or key limits retain the billing interruption flow. Each automatic retry restarts the whole unfinished cell, with a new model call; completed cells are never retried. Provider messages and codes are persisted in cell metadata and returned to the client, without raw request bodies or response headers. Streaming drafts remain in memory and are broadcast at most once per 300 ms per grid, with cell transitions persisted and emitted immediately.

Generation has no application output-byte or bundle-file-count limit. Grid creation requires a positive `budgetUsd` setting; the form starts at $5 per cell attempt. Text generation always resolves catalog pricing and computes a token ceiling before calling the provider. Catalog discovery retains USD/token input and output rates, per-request charges, context length, and the advertised completion ceiling. `server/generation-budget.ts` reserves an input estimate of UTF-8 prompt/system bytes plus 256 tokens of message overhead, then divides the remaining dollars by the output-token price and floors the result. The output limit also respects the advertised model completion ceiling and remaining context. Free output uses that model ceiling. Missing pricing or context information fails the cell before an inference call. The provider route is constrained to those prompt/completion rates through `provider.max_price` in USD per million tokens. Each cell makes one model call using the full allowance. Each text request sends an explicit `max_tokens` through the SDK's `maxOutputTokens`; reasoning and visible output share it. Input tokenization, provider overhead, and billing variations make this an estimated monetary ceiling. Retries receive a fresh allowance, while completed cells keep their previous outputs. Image generation uses the dedicated image API without this text-token budget. Finish reasons and reasoning-token counts are stored exclusively in the billing ledger and omitted from grid snapshots. Cell usage comes directly from the latest call, while billing retains all historical calls. Only `stop` is accepted as successful text completion; other reasons fail the cell while retaining reported usage and cost. Thinking-only exhaustion of the requested token limit has a specific error; other incomplete responses use the generic error. Images retain the reported finish reason when available, otherwise successful image generation establishes completion. Finish metadata and per-call usage are persisted in the inference ledger, with cell usage derived from its latest call; finish reasons are omitted from billing responses and have no UI display. The private billing API returns 50 calls per page and totals all reported charges, including earlier retries. Entries are created at inference dispatch, retain errors and cancellations, and are marked interrupted by explicit startup recovery if the process ended before completion. Missing provider charges remain unknown. SVG output is stored verbatim without markup validation; incomplete or unconventional SVG does not fail generation. Website responses are parsed directly as JSON without removing fences or trimming the response. Website bundles must contain `index.html`, safe relative paths with html/css/js/json/txt/svg/md extensions. Website models advertising `structured_outputs` receive a strict schema for a list of file paths and contents; other models are prompted for the same list without provider schema enforcement. Both paths use the same streaming parser and validate the completed bundle. The website schema is shared by the SDK request and final validation. Provider tests cover capability routing and rejection without downgrade, and browser tests cover streamed website content, JavaScript execution, and pause/resume for both paths. The real-provider suite uses an explicit free schema-capable model. Models and their reasoning capabilities are discovered from OpenRouter and cached for five minutes. The form warns about incompatible output formats, mandatory reasoning disabled through None, unsupported effort levels, and explicit efforts whose router capabilities are unpublished. Model default leaves reasoning settings to the model, and minimal is available alongside the other gateway effort levels. These warnings are advisory: creation, retries, and provider calls send the selected settings without requiring catalog approval. Structural input validation and the requirement to use enabled prompt variables still apply. Provider availability and restrictions that are not published in metadata can still cause retryable generation failures. No automatic data retention or database cleanup runs. Sessions expire 30 days after creation. Private output routes and HTML assets require an authorized session; only published outputs are available without one. Output-access integration tests cover all formats, previews, downloads, session expiry, revoked grants, account ownership, and publication. The HTTPS browser regression uses sibling output hosts to verify private stylesheet and module loading, imported assets, direct output navigation before visiting the grid, opening output tabs, reloads, and authorization across session rotation. Account coverage claims an anonymous grid and opens the same direct output URL in two independent sessions of the owning user, revokes one session while the other keeps working, and rejects a different account and an unauthenticated visitor. It also checks that generated documents cannot regain network access by removing the bootstrap's restrictive CSP meta element. Image/SVG cache coverage checks reuse without transferring bytes across page visits, rejects a private cached response after the session cookie is removed, and permits public cache reuse across cookie changes. Route coverage bounds freshness by a nearly expired session and verifies that conditional requests cannot bypass expiry.

## Publishing and listings

Grid visibility uses `private`, `unlisted`, and `public`, while `published` retains the generation lock. `POST /api/grids/:id/publish` requires `{ visibility }`. An already published grid accepts its existing visibility, and its owner can promote an unlisted grid to public visibility. `GET /api/grids/public` returns public summaries without ownership or cell data, newest first. Both summary APIs include output format and visibility. The publish dialog remembers confirmation suppression under `slopgrid-skip-publish-confirmation` in local storage after successful confirmation. Listing format icons use Tippy on hover and keyboard focus. Publishing tests cover access, immutable visibility, summary filtering, and persistence; browser tests cover the dialogs and saved preferences, navigation from public discovery on the creation page, and hiding discovery after output-type selection and draft restoration.

## Generation process control

`pnpm generation status` reads the engine instance and workload counts. `pnpm generation drain` closes admission and waits for accepted grids and unsettled requests to finish. `pnpm generation accept` reopens admission, including when cancelling a planned machinery update. These commands require the same runtime configuration as the application and connect only through its private socket. A drain has no inference timeout and does not cancel user work.

A web restart can briefly disconnect browser streams; generation continues, and reconnecting browsers receive the latest complete snapshot. Engine code, shared storage, and protocol changes must use machinery updates. A soft update must leave the running engine's release files and dependencies unchanged. Both mocked and real-provider browser suites use a separate inference child process. The process-lifetime regression additionally replaces the web child during an active streamed call and verifies queue draining and recorded costs.
