## Requirements and setup

Use Node.js 22.12 or newer and pnpm 12.4.2. The same-site HTTPS browser test uses OpenSSL to generate a temporary test certificate. Supply `GITHUB_CLIENT_ID` and `GITHUB_CLIENT_SECRET` through private runtime configuration before starting the app; either missing or empty variable prevents startup. SQLite uses `better-sqlite3`; environments without a matching prebuilt binary need Python and a C/C++ build toolchain. Native build permissions are in `pnpm-workspace.yaml`.

```sh
pnpm install
pnpm exec playwright install chromium firefox
pnpm dev:engine
# In another terminal:
pnpm dev
```

Open http://localhost:3000. Chromium resolves HTML output hosts ending in `.localhost` to loopback. Images, Markdown, and SVG use paths on the application origin. OpenRouter OAuth supports localhost callbacks. The development server creates a SQLite database and encryption key under `.data/`; preserve both to retain sessions. Manual API keys are entered through the shared connection control and saved only in browser localStorage. OAuth credentials retain their existing encrypted server-side storage.

### Test design

1. Use pnpm and Playwright, with real-provider browser suites separate but enabled in the default full run. Exercise the normal manual-key flow with a cheap or free model and cover structured website streaming with an explicitly selected capable model.
2. Assertions enforce complex behavioral properties: state transitions, persistence, ownership, recovery, and component interactions. Exclude static copy assertions, trivial assertions, constant checks, CSS appearance tests, and checks that merely mirror implementation.

## Runtime configuration

`pnpm build` checks TypeScript and creates the frontend build. `pnpm start` serves that build in production mode and connects to the separately managed inference process started with `pnpm start:engine`. The production process requires `APP_ORIGIN`, `OUTPUT_DOMAIN`, and `KEY_ENCRYPTION_SECRET` to be provided in its environment.

| Variable                | Behavior                                                                                                                                                          |
| ----------------------- | ----------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `APP_ORIGIN`            | Application origin, including scheme and optional port; HTTPS is required in production.                                                                          |
| `OUTPUT_DOMAIN`         | HTML output host suffix beginning with a hyphen, with an optional port; joins the cell ID in one DNS label. Images, Markdown, and SVG use the application origin. |
| `KEY_ENCRYPTION_SECRET` | Exactly 64 hexadecimal characters representing the persistent 32-byte encryption key. Required in production.                                                     |
| `DATABASE_PATH`         | SQLite file path; defaults to `.data/slopgrid.sqlite`. Its parent directory must exist.                                                                           |
| `OUTPUTS_PATH`          | Directory for generated output files; defaults to an `outputs` directory beside the SQLite database.                                                              |
| `PORT`                  | Listening port; defaults to 3000.                                                                                                                                 |
| `BIND_ADDRESS`          | Listening address; defaults to `127.0.0.1`.                                                                                                                       |
| `GENERATION_SOCKET`     | Private Unix socket shared by web and inference processes; defaults to `generation.sock` beside the database.                                                     |
| `GENERATION_DRAINING`   | Set to `1` to start the inference process with admission closed.                                                                                                  |
| `FRONTEND_PATH`         | Frontend build directory served by the web process; defaults to `dist`.                                                                                           |
| `OPENROUTER_BASE_URL`   | Provider API base URL for both processes; defaults to the OpenRouter API.                                                                                         |
| `WORKERS_MAX`           | Maximum concurrent cell generations across the inference process; defaults to 100 and must be a positive safe integer.                                            |

Development creates a local encryption key automatically. Changing the encryption key makes existing stored credentials unreadable. Run exactly one inference process per database. The web process connects through the configured generation socket and can restart independently. Both processes must use the same database, output directory, and encryption key.

## Storage

SQLite stores grid configuration, cell state, encrypted OpenRouter session credentials, users, and provider identities. Provider identities are keyed by provider and provider subject. GitHub access tokens are used only for profile retrieval and are not persisted. Generated output bodies live on disk, with one directory per cell; image files contain binary bytes and website files retain their relative paths. Streaming drafts remain in memory. Changing metadata or publishing a grid never rewrites its completed output files.

`server/database.ts` defines the current schema. Startup creates it atomically for an empty database, accepts the current SQLite `user_version`, or upgrades version 8 to version 9 by adding reference-image metadata without changing existing records. Storage and route tests exercise persistence and reopening; upgrade and unsupported-version tests check that existing data is preserved.

SQLite backups and output-directory backups, including uploaded references, must be kept together, along with the encryption key needed to read stored credentials. Temporary output directories can remain after a process crash; an unfinished cell stays retryable, and retry replaces any uncommitted output for that cell. Completed outputs are not automatically removed; temporary website previews are cleared at inference-process startup and when an attempt ends.

## Operational limits

Each browser session can create ten grids and retry thirty times per hour; each client IP can create thirty grids per hour. API traffic other than model-list GET and HEAD requests is limited to 600 requests per client IP per minute, and generated outputs to 2,000 requests per client IP per minute, with 20,000 requests per minute for website preview paths to support repeated bundle refreshes. Creation and Resume check the authenticated OpenRouter credit balance before starting inference. For image generation, a balance below $3 returns a `LOW_BALANCE` response without starting work; explicit continuation permits automatic parallelism. Text generation proceeds to OpenRouter admission at the calculated parallelism. `GET /api/inference-capacity?format=image` returns the authenticated balance and recommended count `max(1, floor(balanceUsd / 0.4))`. Without cell data, text capacity responses use the $3 fallback. Text start/resume admission sums per-cell estimates in dispatch order until the next cell would exceed balance, with at least one worker and at most the remaining cell count. Each estimate includes expanded prompt/system input, request fees, and budget-capped output within model/context limits. Missing pricing or limits, incomplete charges, and preparation errors contribute $3 individually. Unavailable manual-key credits yield one worker; responses are uncached and limited to 60 checks per session per minute. The API accepts an optional positive integer `parallelWorkers`. The creation form omits it for automatic text selection and submits the automatic image recommendation. Automatic admission uses unfinished cells after artifact reuse and on Resume. Fully reused grids skip the inference balance check. Each start/resume check stores this requested count, or the automatic recommendation for the grid's output type when omitted, as the session concurrency limit. Each grid also respects its own requested count, so another grid raising the session limit cannot exceed that request. The session limit applies across its grids and remains subject to the shared `WORKERS_MAX` cap. Balance lookup failures prevent new inference and surface an error. Existing in-flight calls are allowed to finish when the limit changes. Grids queue their cells in a shared worker pool, with up to `WORKERS_MAX` concurrent cell generations. Allocation counts all active cells across each browser session's grids. Each free slot goes to an eligible session with the fewest workers; ties favor the least recently allocated session, with unserved sessions first. All available capacity is used, with no reserved slots or cancellation for rebalancing. Manual pause aborts active requests for that grid and removes its queued work until resume. Non-transient HTTP 402 and documented key, workspace, or guardrail budget HTTP 403 failures pause queued work for that session, while its already active calls can finish. Other permanent inference failures mark only the affected cell as failed and release its worker so queued cells continue. Missing execution credentials follow the same cell failure path. A worker slot covers the whole cell, with one model call per attempt. SSE is limited to five connections per session and 100 globally; the client keeps a connection only while the grid can change through active or queued generation, closing it when stable and reopening it after resume. These counters are in memory and reset on restart. OpenRouter requests have no application deadlines or HTTP client connection, header, or body timeouts. Manual pause still aborts inference, and SDK automatic retries are disabled. The scheduler retries HTTP 429 and HTTP 402 errors identified as in-flight budget exhaustion with valid Retry-After guidance, with up to five retries per cell. A billing error without valid guidance pauses queued work until the user resumes. Tests cover missing and malformed guidance, HTTP and streamed metadata headers, elapsed cooldowns, and explicit Resume. Delays start at one second, double after each failure, include up to 50% jitter, and honor longer Retry-After values given as seconds or an HTTP date. A cooldown applies across the browser session's grids; waiting cells release worker slots, and existing requests can finish. Retry counts and cooldowns are process-local. Manual pause stops queued retries, while Resume still honors an unexpired cooldown. Genuine credit or key limits retain the billing interruption flow. Each automatic retry restarts the whole unfinished cell, with a new model call; completed cells are never retried. Provider messages and codes are persisted in cell metadata and returned to the client, without raw request bodies or response headers. Streaming drafts remain in memory and are broadcast at most once per 300 ms per grid, with cell transitions persisted and emitted immediately.

## Generation process control

`pnpm generation status` reads the engine instance and workload counts. `pnpm generation drain` closes admission and waits for accepted grids and unsettled requests to finish. `pnpm generation accept` reopens admission, including when cancelling a planned machinery update. These commands require the same runtime configuration as the application and connect only through its private socket. A drain has no inference timeout and does not cancel user work.
