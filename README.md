# slopgrid

Compare generated outputs in a grid. Choose models, thinking effort, or prompt variables, then generate SVG, Markdown, static websites, or images using your OpenRouter account.

## Create a grid

1. Select the slopgrid logo to open your grid list, then select **NEW GRID** and choose the output format to reveal the full creation form. On mobile, open the hamburger menu to find **SETTINGS**.
2. Choose what rows and columns represent, then select their values. Use the swap icon between their selectors to exchange the axes and selected values; prompt variable references swap with them. Filter model lists by name or ID to find the models you want to compare. Selected models appear as badges below each model list; use a badge’s cross to remove that model, even when it is hidden by the filter. Thinking effort axes follow effort order rather than selection order. For prompt variables, enter one value per line. Image grids support models and prompt variables.
3. Enter your prompt. Use `$VARIABLE_ROW` and `$VARIABLE_COLUMN` to insert each cell's row and column values when those dimensions are prompt variables. Each enabled variable must appear in the prompt before you can generate.
4. Connect OpenRouter or select **Use API key**, set **Budget limit per cell** for SVG, Markdown, or websites (default $5), and select **Generate**. This covers the estimated input and output cost of one cell attempt, including thinking. Each cell makes one model call. A retry starts a new allowance. Prices and input token counts are estimates, so actual charges may differ. Image generation uses the image provider’s pricing and has no token-budget field. If your OpenRouter balance is below $3, top up from the popup and select **Check balance again**, or choose **Continue anyway** to use your selected parallelism. The same balance check applies when resuming. **# of parallel workers** starts at your available balance divided by $3, rounded down, with a minimum of one and a maximum of the grid’s cell count. You can enter another count or select **MAX** inside the field to request one worker per cell. The selected count is saved with the grid and reused on Resume. Actual parallelism depends on shared capacity and fair allocation across users.

When model or thinking effort is not a dimension, its selection applies to the whole grid. **Model default** lets each model choose its own thinking configuration. The thinking effort compatibility table compares your selected models and efforts against OpenRouter’s published capabilities. A checkmark marks a supported combination; other cells are blank, with hover labels distinguishing unsupported settings from unknown support. The table also includes the fixed model or effort when it is not a grid dimension, and does not block generation. OpenRouter may reject unsupported settings, which appear as cell errors. **Model default** leaves thinking settings to the model when effort information is unavailable. A grid can contain up to 64 outputs, with up to eight values per dimension.

Model aliases with an exposed target are resolved when you generate, and only the concrete model IDs are saved. Edit, Fork, and retries reuse those IDs, even if the alias later changes. If an alias and its target are both selected on the same axis, they become one model entry. Aliases without an exposed concrete target cannot be used; choose a versioned model instead.

## Watch generation

The grid fills the page below the header, which shows your prompt, a generation progress bar, and publishing controls. Outputs generate in parallel as capacity becomes available, with free capacity going to users currently running fewer outputs. The progress bar has one segment per output in grid order: completed outputs use the normal accent color, failed outputs appear red, and unfinished outputs remain unfilled. Both completed and failed outputs count toward progress. The grid updates as generation progresses. Markdown renders as it streams in the same cell preview used for the finished output; raw view and expansion are available during generation. SVG cells show a partial image while generation is running, completing unfinished markup for the preview and replacing it with the final output when ready. Website cells show the growing bundle as HTML, CSS, JavaScript, and other files arrive, including unfinished file contents. Previews refresh periodically, so interactions may reset until generation finishes. Pause discards the temporary preview. Completed outputs remain available when you reload the page. Output rows expand to fill the available page height while the header keeps its natural height. Resized output rows retain their saved heights. Row and column headers stay visible as you scroll. Drag a column label’s left edge or a row label’s top edge to resize that output column or row. Each shared edge controls the column to its right or the row below it, including the last row. The heading row and label column keep their automatic sizes, while output sizes are saved separately for each grid in this browser. You can also focus an edge and use the arrow keys, holding Shift for larger steps. Select the **Open output** arrow icon to view a result in a separate tab. The bottom-left controls also let you **Copy output** or **Download output**. Copy uses SVG or Markdown source text, or the generated image; websites have no Copy button. Website downloads contain the full generated bundle in a ZIP with its relative file paths preserved. Download filenames follow `<prompt>.slopgrid.com.<grid-id>.<row_parameter>.<column_parameter>.<extension>`, using the grid prompt and selected row and column values. Spaces and punctuation in those values become underscores, and long components are shortened to keep the filename within 240 characters. Click or tap the model ID in a row or column label to copy its full ID; the chain icon beside the copy icon opens the model’s OpenRouter page in a new tab.

On devices with a touchscreen, the grid starts scaled to fit the available width, regardless of screen size. Pinch with two fingers inside the grid to zoom the table, then swipe with one finger to scroll. The header stays at its normal size, and zooming out stops when the table fits within the available width. Zoom resets to fit the width when the grid viewport changes size. Markdown code blocks retain their full line widths, and the entire document scales down to fit the preview width. Markdown previews scroll vertically with one finger inside the cell and pass two-finger gestures to the grid for zooming. Select **View raw** beside the expand icon to show the original Markdown as plain text, preserving line breaks without wrapping and scaling to fit the cell’s width, then select the **View Markdown** (MD) icon to restore the rendered view. The selected view is preserved when expanding or collapsing the cell. Select the expand icon in a Markdown cell’s top-right corner to fill the grid workspace while keeping the navbar visible, then use the collapse icon or Escape to return to the table. Your table zoom, position, and preview scroll position are preserved. Website frames support their own scrolling and interactions; start grid gestures on the table headings, or use the **Open output** arrow icon to view a website separately.

The cost beside the grid title adds completed output prices and current in-progress estimates, then truncates the displayed total to two decimal places. Individual cell prices retain their precision. Streaming text cells show an estimated dollar amount marked **≈**, which grows as output and available reasoning arrive; the grid total carries the same mark while it includes estimates. Completion replaces the estimate with the OpenRouter-reported charge. Failed, paused, and earlier retry attempts are excluded from this total. Each completed cell also shows input tokens with an upward arrow and output tokens with a downward arrow. Missing reported charges appear as unavailable and are excluded from the total. Image prices appear when generation finishes.

Use the pause button beside the prompt to stop unfinished requests and discard partial previews, then select resume to generate the unfinished cells again. Completed outputs are preserved.

Temporary rate limits and in-flight spending limits retry automatically, with up to five retries per unfinished cell and increasing waits that honor the provider’s retry delay. Waiting cells show **Waiting to retry…** and the provider’s error code and message. Other users can keep generating while your requests wait, and Pause stops queued retries. Retries restart the unfinished cell, while completed outputs remain unchanged. Failed cells retain their error code and message after reload and publication.

If OpenRouter reports a billing problem, check your credits and key spending limit, then select **Retry unfinished cells**. You can close the popup and resume later using the button beside the prompt. Completed cells are saved and are never regenerated by retries. If OpenRouter rejects your key, reconnect OpenRouter. Work interrupted by a server restart also requires an explicit resume.

Before publishing, select the pencil button (**Edit**) to return to parameter selection with the current setup and prompt restored. This immediately cancels active inference and discards partial results. Generating from the edited setup creates a new grid; the previous grid remains in **YOUR GRIDS** with its completed outputs.

## Publish and share

Select the upload button (**Publish**) after every output has finished, whether it succeeded or failed. In **Control who can see this grid**, choose **Keep private**, **Accessible by link**, or **Listed publicly**, then select **Save**. Link access makes the prompt, dimensions, and outputs accessible to anyone with the grid link. Publicly listed grids also appear under **Public grids**, below **Your grids**. Each listing shows an output format icon; hover over it or focus it to see the type. Publishing requires confirmation unless you previously selected **Don’t ask again** in this browser. After publishing, the grid contents cannot be changed and the grid cannot be made private. To list a link-only grid publicly, select the eye button (**Change visibility**), choose **Listed publicly**, and select **Save**. Publicly listed grids cannot return to link-only visibility. Use **Copy link** to share it. Failed cells remain visible in published grids. Select the fork button (**Fork**) to copy a published grid’s setup into the parameter form, change its settings or prompt, and generate a new grid using your own OpenRouter connection.

Select the slopgrid logo to find your grids; the grid list also has a **NEW GRID** button. You can use slopgrid anonymously, with grids tied to this browser’s session, or select **Sign in with GitHub** in the header or Settings. Signing in adds this browser’s anonymous grids to your account and makes your grids and billing history accessible from other browsers signed into the same account. OpenRouter connections and manually entered keys stay in the browser where you connected them. Select **Sign out** in Settings to return to anonymous use. Private outputs, previews, and downloads require the owning browser session or a session signed into the owning account. Sharing an output URL does not give another visitor access until you publish the grid.

Published grids show **by Anonymous** if you publish anonymously, or your GitHub icon and linked username if you publish while signed in. Publication fixes this attribution; signing in later does not change authors on previously published grids. Drafts show their owner’s current identity, and listings include the author beside each grid.

## Billing history

Open **BILLING** to see every recorded inference attempt, including automatic retries, failures and cancellations. Each entry identifies its grid by the prompt and links to it and shows its status, reported token usage, cost, and any error code and message. The total includes all reported charges in this history; missing charges are marked unavailable rather than counted as free. History is private to your signed-in account, or to this browser session when you use slopgrid anonymously, and begins when call recording is enabled; earlier requests are not reconstructed.

## OpenRouter settings

Open **SETTINGS** to choose **System**, **Light**, or **Dark** appearance. **System** is the default and follows your device’s current preference; explicit choices are saved in this browser and also apply in other open tabs.

The OpenRouter row shows your connection status. Select **Connect** when disconnected; once connected, use **Disconnect** or **Change connection** in Settings. On the creation page, the connected row links to Settings. While the connection is being checked, the row shows that status, and a failed check offers **Check again** without claiming that you are disconnected. To use your own key, select **Use API key**, enter **API key**, and select **Connect**. The key is saved in this browser and sent when checking available credit, generating, or resuming; it is held in server memory only while the grid runs. It takes precedence over an existing OAuth connection. Choosing **Change connection** returns to OAuth and removes the local key. When account credits cannot be read, a finite key spending limit determines the worker recommendation; otherwise the recommendation is one. Generation uses your account's credits. Disconnecting removes the saved connection; an already-running grid may continue until you pause it.

Generated websites run in an isolated sandbox. Static HTML, CSS, and JavaScript are supported; server-side code, network requests, forms, and browser cookies are blocked. Images and SVG render as images, with SVG scripts and external resources disabled. Opening an SVG output directly retains script and cookie restrictions, while direct Markdown output pages also disable scripts and cookie access. Markdown previews render React elements inside a scrollable cell, with raw HTML shown as text, unsafe links removed, and external images blocked.
