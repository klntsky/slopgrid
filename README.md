# slopgrid

Compare generated outputs in a grid. Choose models, thinking effort, prompt variables, or harnesses, then generate SVG, Markdown, static websites, or images using your OpenRouter account.

## Create a grid

1. Select **NEW GRID** in the navigation bar, then choose the output format. On mobile, open the hamburger menu to find **NEW GRID**, **YOUR GRIDS**, and **SETTINGS**.
2. Choose what rows and columns represent, then select their values. Filter model lists by name or ID to find the models you want to compare. Thinking effort axes follow effort order rather than selection order. For prompt variables, enter one value per line. Image grids support models and prompt variables.
3. Enter your prompt. Use `$VARIABLE_ROW` and `$VARIABLE_COLUMN` to insert each cell's row and column values when those dimensions are prompt variables. Each enabled variable must appear in the prompt before you can generate.
4. Connect OpenRouter and select **Generate**.

When model, thinking effort, or harness is not a dimension, its selection applies to the whole grid. **Model default** lets each model choose its own thinking configuration. Before generation, Slopgrid checks every selected model and effort against OpenRouter’s published capabilities. Warnings name each incompatible model and setting, list supported alternatives, but let you generate with the selected settings anyway. OpenRouter may reject unsupported settings, which appear as cell errors. **Model default** leaves thinking settings to the model when effort information is unavailable. **Single pass** makes one request per cell. **Draft and review** generates a draft and makes a second request to check and revise it. A grid can contain up to 64 outputs, with up to eight values per dimension.

## Watch generation

The grid fills the page below the header, which shows your prompt, a generation progress bar, and publishing controls. Outputs generate in parallel as capacity becomes available, with free capacity going to users currently running fewer outputs. The progress bar has one segment per output in grid order: completed outputs use the normal accent color, failed outputs appear red, and unfinished outputs remain unfilled. Both completed and failed outputs count toward progress. The grid updates as generation progresses. SVG cells show a partial image while generation is running, completing unfinished markup for the preview and replacing it with the final output when ready. Completed outputs remain available when you reload the page. Row and column headers stay visible as you scroll, with labeled dimensions in the corner. Select **Open output** to view a result in a separate tab. Click or tap the model ID above an output, or in a model row or column label, to copy its full ID.

On mobile, pinch with two fingers inside the grid to zoom the table, then swipe with one finger to scroll. The header stays at its normal size, and zooming out stops when the table fits within the available width and height. Zoom resets when the grid viewport changes size. Website and Markdown previews let these gestures reach the grid; use **Open output** to interact with a generated website or scroll a Markdown document separately.

Each completed cell shows token usage and its OpenRouter-reported cost in USD; draft and review includes both requests. If any request lacks a reported charge, the cost is shown as unavailable. Charges for aborted or failed attempts are not included in the completed output’s cost.

Use the pause button beside the prompt to stop unfinished requests and discard partial previews, then select resume to generate the unfinished cells again. Completed outputs are preserved.

If OpenRouter reports a billing problem, check your credits and key spending limit, then select **Retry unfinished cells**. You can close the popup and resume later using the button beside the prompt. Completed cells are saved and are never regenerated by retries. If OpenRouter rejects your key, reconnect OpenRouter. Work interrupted by a server restart also requires an explicit resume.

Before publishing, select **EDIT** to return to parameter selection with the current setup and prompt restored. This immediately cancels active inference and discards partial results. Generating from the edited setup creates a new grid; the previous grid remains in **YOUR GRIDS** with its completed outputs.

## Publish and share

Select **PUBLISH** after all outputs generate successfully, then **Copy link** to share the grid. Publishing makes the prompt, dimensions, and outputs accessible to anyone with the link. Published grids cannot be changed. Select **FORK** to copy a published grid’s setup into the parameter form, change its settings or prompt, and generate a new grid using your own OpenRouter connection.

Open **YOUR GRIDS** in the navigation bar to find grids created in this browser. Selecting the slopgrid logo opens **YOUR GRIDS** when you have created at least one grid, or the creation form when you have none. Keep that browser's cookies: ownership is tied to a 30-day browser session, with no separate slopgrid login or cross-device account. Each completed output has an unguessable URL that can be opened directly; anyone who receives that output URL can view it, even before the grid is published.

## OpenRouter settings

Open **SETTINGS** to choose **System**, **Light**, or **Dark** appearance. **System** is the default and follows your device’s current preference; explicit choices are saved in this browser and also apply in other open tabs.

You can also connect, reconnect, or disconnect OpenRouter there. Generation uses your account's credits. Disconnecting prevents further requests; an already-running request may still finish.

Generated websites run in an isolated sandbox. Static HTML, CSS, and JavaScript are supported; server-side code, network requests, forms, and browser cookies are blocked. Images and SVG render as images, with SVG scripts and external resources disabled. Opening an SVG output directly retains script and cookie restrictions, while Markdown previews also disable scripts and cookie access. Raw HTML in Markdown is shown as text.
