# Architecture

## Architecture constraints

These constraints define the implementation boundaries for the behavior in [PRODUCT.md](PRODUCT.md).

### Stack and rendering

1. Use TypeScript and React, TanStack Router and Query, and SSE for browser updates. Use the AI SDK for inference and SQLite for persistent application data.
2. Use Lucide for interface icons and Tippy for tooltips. Render Markdown through shared React components without unsafe DOM insertion, and render images and SVG through image elements.
3. Keep identity-provider and inference-provider boundaries separate. GitHub and OpenRouter are the current integrations; provider-specific logic belongs behind those boundaries so additional providers can be added without spreading their logic through the application.
4. Website generation uses one JSON shape for all models: an object whose `files` value is a list of `{path, content}` entries. Share the schema between generation and final validation, including safe relative paths, supported static files, duplicate-path rejection, and the required `index.html`.
5. Require strict structured output and compatible routing for models advertising that capability. Other models receive the same shape through prompting and ordinary JSON parsing. Both paths stream through the same decoder and parse the final JSON directly from the unmodified response; a failed strict request must not silently downgrade.
6. Website previews use at most two iframes: retain the visible frame while the next loads, transfer document and panel scroll positions before swapping, and coalesce intermediate updates. Apply this handoff to saved output as well as streaming snapshots.
7. Include the Markdown renderer in the main frontend bundle, retain hashed assets needed by open tabs, and make missing-asset responses uncacheable.
8. Translate the per-cell monetary budget into an output-token ceiling using model pricing, estimated input cost, and model/context limits.
9. Use this SVG instruction: "Fulfill user's SVG generation request. Your response will be saved directly as an image/svg+xml file. Start immediately with <svg and end immediately with </svg>. Include no introduction, explanation, Markdown fences, or other text outside the SVG element."

### Responsibility and shared contracts

1. Persistence, encryption, and presentation have separate owners; encryption and author/grid response construction live outside the data store.
2. Keep identity claiming and notification/throttling mechanics out of generation orchestration where their actual owner can handle them directly. Use one consistent preview-notification policy rather than duplicated throttle implementations.
3. Provider modules handle provider logic, including catalog, credit interpretation, and SDK adaptation. Keep HTTP request handling and application balance/concurrency policy outside those modules, and share credit lookup rather than duplicating it in manual-key routes.
4. Separate grid input/expansion logic from output protocols, generation instructions, and parsing. Reuse one relative-path validator for output parsing and storage.
5. Share completion-success policy between inference and billing instead of interpreting finish reasons twice.
6. Centralize grid access, publication policy, and author presentation. Use a separate React publishing component with TanStack queries/mutations; let its mutation own request errors instead of duplicating error state in the dialog.
7. Share creation/resume inference-request handling, balance dialogs, and draft persistence instead of maintaining parallel implementations.
8. Deduplicate equivalent UI widgets and behaviors, including modal lifecycle, clipboard feedback, format icons, and tooltip setup.
9. Derive or share API snapshot types so client/server contract drift is impossible. Avoid manually maintaining the same response shape twice.
10. Give table sizing one owner, with explicit cooperation between resizing and zooming.
11. Consolidate output metadata/authorization lookup and filename/MIME selection, while distinguishing running previews from completed saved outputs.
12. Group scheduler state by lifetime in plain per-grid and per-owner records instead of parallel maps with duplicated cleanup.
13. Separate worker allocation policy from execution mechanics. The shared worker limit is configured through `WORKERS_MAX`, with a default of 100.

### Persistence and authorization

1. Use an explicitly, monotonically versioned SQLite schema and support the current version. Store generated bodies as filesystem files, keep configuration once, and derive per-cell settings and call usage without duplicate persistent representations.
2. Keep temporary previews and in-memory drafts separate from committed outputs. Metadata edits and publication must not rewrite output files.
3. Recovery and preview cleanup run explicitly at inference startup; constructing a store or starting the web process must not mutate generation state.
4. Identify GitHub users by stable provider/user-ID pairs. Require configured GitHub credentials at startup, rotate sessions on sign-in and sign-out, and use session-bound single-use OAuth state, expiry, PKCE, and validated local return paths. Discard GitHub tokens after identification and keep provider authorization attempts separate.
5. Form isolated HTML hostnames from an environment-configured suffix within one wildcard-covered DNS label. Host dispatch must isolate generated bundles from application routes and cookies.
6. Private HTML authorization uses a narrowly scoped host-only output cookie bound to a live application session. Every private asset request rechecks session validity and ownership; bootstrap permissions do not extend to generated documents.

### Generation process and update boundaries

1. The inference process owns the complete generation lifecycle: admission, queued/running work, worker allocation, provider calls and execution credentials, retries, cancellation, budget enforcement, output/thinking streams, previews, usage/charges, generation state, and recovery.
2. The web process owns authentication, sessions, account/settings UI, model discovery for creation, grid metadata, authorized output delivery, billing presentation, HTTP routes, and browser event connections.
3. Keep the process API explicit and small, with defined commands and snapshots/subscriptions over local transport.
4. Give generation state and editable metadata separate write ownership. Coordinate publication, ownership changes, and generation admission so stale whole-grid writes cannot overwrite newer state or publish a running grid.
5. Reconnecting browsers receive current ordered snapshots, including partial output, thinking, estimates, and preview identifiers. Subscription registration and initial snapshot delivery must not leave an update gap.
6. Lost command acknowledgements or simultaneous starts must not duplicate inference. Slow or abandoned viewers must not block generation or leak subscription capacity.
7. Use standard HTTP/stream utilities for transport and only the connection monitoring needed to detect disconnection.
8. A soft update replaces web code without touching the running engine's immutable release or dependencies. Engine, shared-contract, schema, and incompatible dependency changes require a machinery update.
9. Machinery updates close admission inside the engine, continue accepted queues and retries, and wait for accepted grids and unsettled calls with no cancellation timeout. Admission can reopen when maintenance is cancelled.

## Implementation

`src/main.tsx` mounts the application providers, `src/router.tsx` defines routes, and `src/layout.tsx` owns the navigation shell and grid header portal target. `src/components/grid-listing.tsx` shares grid-list rendering and the public-grid query section between Your grids and the creation page; creation mounts that section only before output-type selection. Pages live under `src/pages/`, creation controls and draft persistence under `src/create/`, and shared connection controls and inference dialogs under `src/components/`. Grid query/SSE state and edit mutations live in `src/grid/use-grid.ts`, while the header, output table, and individual output cells have separate components under `src/grid/`. The React client uses TanStack Router for creation, grid history, billing, settings, and grid routes, and TanStack Query for API state. Selecting an output type reveals the full creation form, which stores its in-progress state in sessionStorage across OAuth redirects. Grid pages use EventSource while generation is running or a paused grid still has active requests, receiving server snapshots and draft text while text generation streams. The client closes the connection once the grid is stable and reopens it when an action starts generation again. Stable grids do not open a connection when loaded. SVG drafts are completed locally for a disposable image preview: open elements and quoted attributes are closed, unfinished attribute names are omitted, and trailing partial entities are dropped. The browser decodes each candidate as an image before replacing the last valid preview. These changes never modify the stored final SVG; Markdown streams through the shared renderer and websites through bundle previews. Monotonic revision numbers prevent late HTTP responses from overwriting newer SSE state. Each accepted draft update allocates a revision in SQLite, including updates between throttled emissions, while its text stays in engine memory. Streaming output drafts stay in the active worker's memory without being written to SQLite. Provider-exposed thinking is streamed separately and appended to private files under a cell and attempt identifier. Cell metadata stores the latest thinking identifier; earlier attempt files remain separate. Partial thinking survives pauses, failures, and restarts, while a newly dispatched attempt clears the current identifier before receiving new text. SVG and Markdown draft text is included in live snapshots; website snapshots contain only a versioned preview URL rather than the bundle text. Website cells receive file snapshot URLs through the existing grid SSE connection. Each keeps its loaded iframe visible while a second, hidden iframe loads the next snapshot, then swaps the frames without remounting the new document. Before revealing a replacement, `src/grid/frame-scroll.ts` reads the visible document's current viewport and nested-panel scroll offsets through a MessageChannel, applies them to the hidden document, and waits for acknowledgement. Nested panels match by element ID or structural CSS path; missing elements are skipped and offsets clamp to the replacement's available content. If a document no longer responds to the bridge, a short timeout lets the swap proceed. Updates arriving during a load are coalesced to the latest URL for the next load, keeping at most two frames mounted. The same handoff applies when streaming finishes and the saved output replaces the preview. Private frames wait through both the authorization bootstrap and generated-document load events; published frames need only the document load. Pausing or failing a cell unmounts its frames. Images and SVG render directly as image elements; HTML previews use sandboxed iframes with scripts allowed. Markdown previews render streamed drafts and completed source with the same mounted `react-markdown` and `remark-gfm` component. Completion fetches the original Markdown file through the output route's raw mode while retaining the last streamed draft, so the document and scroll container remain mounted. The cell reserves its footer space during streaming and keeps raw-view and expansion controls available throughout. The parser is included in the main browser bundle, and unchanged Markdown content is memoized across grid updates. Markdown raw view preserves source line breaks without wrapping and uses the same width fitting as rendered Markdown. A ResizeObserver measures the document with full-width code blocks or raw text in unscaled CSS pixels and applies CSS zoom to fit the preview width; the preview allows only vertical scrolling and recalculates after resizing or image loads. The shared `shared/markdown.tsx` component also renders direct output pages through React server rendering, so both views use the same parser and URL policy. Raw HTML remains escaped text without HTML parsing plugins or DOM insertion. Links, images, and task lists use the renderer and plugin defaults. Vite selects the entity decoder's lookup-table implementation rather than its browser implementation that writes to innerHTML. Grid pages render their title, pause/resume control, accessible progress bar, and action buttons into a header slot through a React portal. The progress bar spans the bottom of the header and counts complete and error cells as finished. Visual segments follow cell order, coloring successful outputs with the accent and failed outputs red, while the native progress element exposes the finished count and separate success/failure totals to assistive technology. A moving, pulsing spark appears during generation, with reduced-motion support. Live cost and owner spending text use the same CSS gradient animation while the grid or any cell is running; reduced-motion preferences show static text. The shell fills the viewport and gives the remaining space to the grid scroll container. Tables fill the available width and scroll with sticky column and row headers and an empty corner cell. `src/grid-resize.ts` owns table width and output-row height for both automatic layout and saved sizes. The zoom component calls its viewport-fit function before measuring the scale, and its viewport observer requests a fresh fit after viewport changes. For unresized tables, sizing distributes spare vertical space to output cells after subtracting the natural header height, with a 390-pixel minimum per output row. The table itself has automatic height, so viewport filling cannot stretch the header; saved output row heights take precedence. The row-label column sizes to its rotated contents and padding, while output columns initially retain a minimum width of 340 CSS pixels. Resize handles on column labels' left edges and row labels' top edges adjust the output column to the right or row below, switching to explicit table dimensions on the first resize. The heading row and label column have no resize handles. The heading row keeps its natural content height when saved output sizes are restored or changed, while the label column retains its measured automatic width. Only output dimensions are stored per grid in localStorage, with no server persistence. Pointer deltas account for table zoom, and the handles also accept arrow keys. On mobile, navigation moves into an anchored hamburger menu that closes after a link selection, an outside pointer press, Escape, or a route change. Model IDs in row and column labels use clipboard buttons with a success icon and an accessible status message. `src/zoomable-grid.tsx` handles two-finger touch gestures inside the grid at any screen size, scales only the table with CSS zoom from the scale that fits the table within the viewport up to 3x, and adjusts scroll offsets around the fingers' midpoint. Touch-capable grids, detected through `navigator.maxTouchPoints` or an available coarse pointer, start at the scale that fits their full width, with their base table width fixed before applying zoom. One-finger scrolling stays native. Resizing the viewport reapplies the width fit on touch-capable devices and restores normal scale on devices without touch, and HTML frames retain native pointer input and scrolling; grid gestures can begin on table headings. Markdown previews use native nested scrolling for one-finger gestures, while two-finger touch events bubble to the grid zoom handler. `OutputGrid` can expand one running or completed Markdown, SVG, or image cell into an overlay constrained to the grid workspace, keeping the navigation header visible and the underlying table mounted but hidden and inert. Expansion shares the cached Markdown source and transfers its scroll position; images use the same contained-image component at the larger size, and SVG previews keep receiving current drafts. Collapsing restores focus to the original expand button on collapse; Escape also closes the overlay. Table zoom, sizing, and scroll offsets remain intact. Theme colors use CSS variables for light and subtly warm dark palettes. A small external bootstrap script applies the saved browser preference before rendering, while a React provider follows system appearance changes, persists explicit overrides in localStorage, synchronizes open tabs, and updates the browser theme color. Generated output canvases retain their own appearance.

`server/app.ts` composes the application dependencies and middleware in request order. `server/frontend.ts` serves the built client with uncached page entries and immutable hashed assets. Markdown previews import the shared renderer directly into the main bundle rather than loading a separate module chunk. Rebuilds retain existing assets for pages opened before an update, and missing asset responses are not cacheable. Host dispatch and generated HTML isolation live in `server/hosting.ts`; API origin and rate checks live in `server/security.ts`. Cookie/session handling, rate limiting, and grid snapshot presentation have dedicated modules. The private billing router pages inference attempts by session ownership, omits finish reasons from its response, and provides totals for reported charges and unavailable costs. Routers under `server/routes/` handle authentication, model listing, grids, SSE, and same-origin outputs; the inference guard owns the balance check and session concurrency policy. The server entry point serves the built client in production and Vite middleware in development. Grid creation and Resume query OpenRouter credits before starting work. Balances below $3 require explicit continuation, shown through a top-up dialog. The inference policy also supplies the authenticated `GET /api/inference-capacity` recommendation, `max(1, floor(balanceUsd / 3))`, through a TanStack query. Creation caps that recommendation at the cell count until the user overrides it; MAX selects the cell count. The form submits and saves `parallelWorkers` in the grid input, preserving the request through Resume and Edit/Fork. Each accepted start or resume sets the session limit to the saved request, falling back to the recommendation when no count was supplied. The scheduler applies this limit across the session's grids alongside fair allocation and the shared worker cap. `server/domain.ts` validates grid inputs, expands their Cartesian product, and substitutes prompt variables literally. `server/output-format.ts` owns generation instructions, the website schema, and completed-output parsing, reusing the storage path validator for generated static bundles. For website models advertising `structured_outputs`, inference requests a strict JSON schema through the AI SDK and requires supporting provider endpoints. The schema uses a list of `{path, content}` entries so arbitrary filenames work with providers that require closed object schemas. Other models receive the same prompted file-list shape without provider schema enforcement. Both paths stream through the same incremental preview decoder and undergo final path, extension, index-file, and duplicate-path validation. Schema failures do not trigger an unconstrained fallback. `server/provider.ts` owns the model catalogs and credit checks, and delegates generation to `server/inference.ts`, which makes one streamed text call through the AI SDK OpenRouter provider or generates images through the provider's image API. `server/billing.ts` owns durable inference-call recording and session-filtered history queries. It reads per-model reasoning metadata, distinguishing explicit effort lists, unrestricted effort selection, unavailable selection, mandatory reasoning, and unpublished router capabilities. `server/http.ts` supplies the shared upstream HTTP transport with connection, header, and body timeouts disabled. Catalog discovery, credit balance checks, OAuth exchange, and inference use this transport, and inference abort signals carry user cancellation without deadlines or application output-byte limits. `server/generation-budget.ts` converts the per-cell dollar allowance into an explicit text output-token ceiling using catalog pricing, a conservative input estimate, and model/context ceilings. Budget configuration lives once in the grid input and is derived into cells when expanding a grid. Inference applies matching provider-price routing constraints and gives the cell call its full allowance; retries start a fresh allowance. Images retain their dedicated API path without a text-token budget. `server/partial-website.ts` decodes file names and JSON string contents incrementally, including unfinished values and escapes split across chunks. `server/website-previews.ts` writes changed files atomically into temporary attempt directories, refreshes each bundle at most once per 750 ms, and clears temporary files on cancellation, retries, and completion. The entry point explicitly clears leftover previews at startup. Preview metadata remains in memory, and preview notifications are coalesced per grid through the scheduler's 300 ms draft throttle. HTML hosts serve both relative preview assets and completed bundles, while the application host serves no generated HTML. `server/failures.ts` extracts provider error messages, codes, retry delays, and transient-limit classification from HTTP and streamed errors. Cell state persists the message and code; a waiting-to-retry flag stays in memory. `server/model-resolution.ts` resolves catalog `alias_target.slug` chains before a grid is expanded or saved. The saved configuration contains only concrete model IDs, with duplicate model-axis targets collapsed; retries and Edit/Fork therefore reuse the pinned selection. Cyclic aliases and latest aliases without a concrete target are rejected. `canonical_slug` differences are not treated as alias markers. `server/compatibility.ts` classifies thinking effort support as supported, unsupported, or unknown. `src/create/compatibility-table.tsx` shows a compact matrix of selected models and efforts, including fixed selections, with SVG checkmarks only for supported combinations. Model default omits reasoning configuration, None sends `reasoning.enabled: false`, and explicit levels send `reasoning.effort` with required-parameter routing. The compatibility table does not block creation, retries, or provider calls; selected settings are sent to OpenRouter, and upstream rejections become cell errors. The inference fetch wrapper creates a durable billing entry before each actual upstream request. Completion metadata stays exclusively in the billing ledger and is omitted from grid snapshots. Each cell's usage is read directly from its latest inference call without attempt grouping or summation. Entries retain the call phase, status, timestamps, available generation ID and HTTP status, normalized and raw finish reasons, reasoning-token counts, token usage, cost, and failure message/code. Retries create new entries. Cancellation is recorded even when the scheduler discards the partial result. No prompts, outputs, credentials, or headers are stored in the ledger. Startup marks unfinished entries interrupted without sending replacement requests. Non-successful text finish reasons fail the cell while preserving its reported usage, without exposing finish metadata in the interface. Reported USD costs are stored in the inference ledger with token usage. Text costs come from provider metadata; a scoped fetch wrapper preserves image response costs because the installed image adapter drops that field. The ledger retains reported charges even for failed calls. Separately, inference estimates streaming text costs from catalog input/output rates and the request fee, approximating one token per four UTF-8 bytes with eight input framing tokens. Provider-exposed thinking text counts toward the estimate without entering the output draft; hidden reasoning, cached input rates, and provider tokenization can differ from this approximation. The scheduler keeps `estimatedCostUsd` only in memory, emits it through grid snapshots, and clears it on completion, failure, pause, and retry. The grid header derives cost from successful completed cells' reported prices plus running cells' estimates. Separately, Billing sums reported charges across all calls belonging to the grid and adds estimates only for running cells whose latest call has no reported cost. This includes failed, cancelled, and retried calls while treating a reported zero as a final price. The engine computes `spentUsd` synchronously with each generation snapshot, so the web process cannot combine an older stream snapshot with newer ledger state. The versioned private API carries this derived field without persisting it in grid metadata; the web presenter removes it for non-owners. Both displayed totals truncate to two decimals. Final reported usage replaces estimates, which never enter the billing ledger.

`server/encryption.ts` provides the authenticated encryption used for stored keys, while `server/grid-presentation.ts` constructs author identities and grid responses. `server/store.ts` stores grid configuration, sessions, and cell state in SQLite with WAL enabled and foreign keys enforced. Grid configuration is stored once, and cell rows contain status, error, and image media type; usage for recorded calls is derived from the latest ledger entry, and finish metadata stays in the ledger; per-cell prompts and model settings are reconstructed from that configuration. The cell ID and position live in relational columns rather than duplicated JSON. Output-host lookups join a cell primary key to its grid rather than scanning grids or maintaining a second output index. `server/routes/outputs.ts` serves completed output downloads on the application origin with attachment filenames built from the saved grid prompt, grid ID, and axis values. Website downloads use `fflate` to generate ZIP archives asynchronously from stored files, preserving relative paths. SVG, Markdown, and image downloads return their original files. Cell clipboard controls copy text source or PNG image data, converting other image formats to PNG for clipboard compatibility. `server/files.ts` stores each output in a directory keyed by its cell ID: text files keep their relative paths, and images are raw binary files. A complete bundle is staged in a temporary directory and renamed into place before the cell is marked complete; interrupted writes cannot expose a partial bundle. A retry replaces any files left by a crash before completion was saved. Generated file bodies are never stored in SQLite or grid snapshots. Completed files are not rewritten when grid state changes.

`server/database.ts` creates the current schema in one immediate transaction for an empty database and checks SQLite's `user_version` on startup. Other schema versions are rejected; there are no historical migrations or legacy data conversions. Each session owns grids through an opaque cookie token. OpenRouter PKCE verifiers and state are server-side; the callback checks state and a ten-minute deadline before exchanging the code. The resulting key is encrypted using AES-256-GCM. Neither keys nor ownership tokens appear in API grid responses.

`server/jobs.ts` manages generation across all active grids, including cell selection, retries, cancellation, previews, persistence, and notifications. `server/worker-allocation.ts` is a pure selection function that applies the shared worker cap, per-owner concurrency limits, and fairness ordering. It derives active counts from the running calls, so there are no separate worker counters to synchronize. Jobs excludes grids already running their requested number of cells before owner selection, counting unsettled canceled calls toward that cap. Jobs records each call's execution owner and keeps concurrency limits and allocation history together in one owner registry, removing idle owners when their grids finish or pause. The configured maximum defaults to 100. Each available slot goes to a browser-session owner with the fewest active cells, with ties resolved by allocation history. Capacity is never reserved, and fair allocation never cancels active calls. Completed cells are skipped on every resume or retry. A manual pause aborts that grid's active requests, discards partial drafts, and stops queued cells. Canceled attempts keep their slots until they settle, and late chunks or results are ignored; resuming cannot start the same cell twice. Billing and authentication failures pause queued work across the owner's active grids without aborting its other in-flight calls. Other failures mark the affected cell as retryable. Parallel cells mutate one canonical grid object, so retries during in-flight work preserve completed results. The generation service supplies Jobs with a save-and-notify callback. State updates are persisted before notifications, while all temporary draft notifications share one per-grid throttle. Only the inference entry point calls `recoverInterruptedGrids` at startup to mark running grids paused and interrupted cells pending; opening a `Store` or restarting the web process does not change generation state. Generation resumes only through an owner-authorized retry. Publishing requires every cell to be complete or failed and freezes further retries.

Each cell receives a random 192-bit output identifier. HTML bundles use a separate hostname formed from that identifier and an environment-configured suffix beginning with a hyphen. Host matching accepts only the configured single-label pattern and exact cell identifier. The iframe CSP uses a whole-label wildcard for the HTML hosts' parent domain, since CSP does not support partial-label wildcards. Host dispatch runs before JSON parsing, session cookies, API routes, or frontend serving. HTML hosts serve only that bundle's validated files, and `/api` cannot reach application handlers there. Their CSP sandbox omits `allow-same-origin` while allowing scripts and static assets; connections, forms, and cookie access are blocked, including when opened in a separate tab.

Images, SVG, and Markdown use `/outputs/:id` on the application host. Images are served as image bytes rather than HTML wrappers. SVG is served as `image/svg+xml` and previewed through an image element, which disables scripts and external resources. Direct visits to the SVG output URL retain the restrictive response CSP. Markdown is rendered with raw HTML escaped. These responses read the existing session without creating one, enforce the grid ownership policy before reading output files, set no cookies, and have a CSP sandbox without script permission. Downloads use the same authorization check before exposing files or filename metadata. The application cookie remains host-only and uses the `__Host-` prefix under HTTPS. HTML bundles cannot be fetched through the application output route, and the HTML host handler serves no other output formats. Completed image and SVG responses use `public, max-age=31536000, immutable` after publication. Private responses use `private, max-age=<remaining-session-seconds>, immutable, must-revalidate` with `Vary: Cookie`; the lifetime is rounded down from the session creation time and the cookie lifetime shared with `server/session.ts`. Changing the cookie selects a different cache entry, and stale entries must revalidate through authorization. Previously cached bytes can remain usable with an unchanged cookie until their expiry without a server check. Other output routes and unsuccessful responses retain `no-store`.

Unpublished grids require their owning account or anonymous browser session for API access. Private outputs and previews require the same ownership as their grid; knowing a cell URL grants no access. Published outputs remain readable without a session.

`server/output-access.ts` bridges application-session authorization to isolated HTML hosts without sharing the application cookie. The application-host entry route checks ownership and the requested file path, then issues an in-memory grant bound to the cell, path, and current session ID. Grants expire after thirty seconds and are capped globally and per owner. Published outputs bypass this handshake.

Private iframe authorization has two phases. Navigation to the isolated host's `/__session/<grant>` endpoint rechecks ownership and the live session, sets an encrypted output cookie, and serves a trusted sandboxed bootstrap. After its load event, its credentialed fetch to the same endpoint sets the cookie in the sandbox's subresource partition, consumes the grant, and receives a 204 response before the bootstrap navigates to the generated document. Navigation deliberately leaves the grant available for this second request. Both phases enforce its expiry and cell binding. Non-navigation clients without the sandbox's null origin receive a redirect after redemption instead.

This bootstrap is needed because navigation and opaque sandbox subresources can use different cookie partitions even with same-site hosts: Chromium includes the cross-site ancestor state in its partition key. Only trusted authorization code can connect to its own host; generated scripts run under `connect-src 'none'` and never receive the application session cookie. The output cookie is host-only, Secure, HttpOnly, SameSite=None, and partitioned. Its encrypted payload contains the cell ID and application session ID, rather than a permanent authorization decision. Every private asset request checks the cell scope, live session, and current grid ownership before reading files or enabling CORS. Session expiry and rotation on sign-out or account switching therefore revoke access even if the output cookie remains in the browser.

`server/website-html.ts` uses parse5 to add credentialed loading to scripts, links, and elements already specifying CORS in private HTML. This carries the output cookie into stylesheet and module requests, including relative imports, while preserving the opaque-origin sandbox. The rewrite affects served HTML only; stored generated files remain unchanged. After authorization, private resource CORS permits credentialed requests from the sandbox's null origin. A null origin alone grants no access, and partitioning separates cookie access across top-level sites. Public files retain credential-free CORS. Served HTML also receives a small scroll bridge before generated scripts. It accepts coordinate read/restore requests only from its immediate parent at the application origin, replies through the supplied MessagePort, and is inactive in direct tabs. Public and private documents use the same bridge without changing their sandbox permissions or authorization; stored files and downloaded bundles do not contain it.

Private top-level HTML navigation without an output cookie redirects through the application entry route, which checks the live session before issuing a grant. The isolated redemption endpoint sets the navigation cookie and redirects to the requested output URL. At that final URL, `server/output-access.ts` issues a fresh grant and serves trusted bootstrap code that fetches the grant endpoint to establish the current document's subresource cookie. It then writes the generated HTML into the same document, preserving its opaque cookie partition and URL. Served HTML places a `connect-src 'none'` CSP meta policy before generated scripts, so the temporary bootstrap connection permission does not extend to them; removing the meta element does not undo the policy. The serialized HTML escapes less-than characters before embedding it in the bootstrap script. Reloading and following another HTML file repeats authorization in that document's partition. Embedded frames retain the application's top-level site and use the two-phase navigation handshake described above. Generated files and downloads remain unchanged.

Publishing requires every cell to be complete or failed; pending and running cells prevent publication. Published grids are readable by anyone with the grid link, including failed cells, and retain the original owner for display controls. Visibility distinguishes private grids, unlisted published grids, and publicly listed grids. Only publicly listed grids appear in the public summary endpoint, which omits owner and cell data. Publishing permanently locks generation inputs and outputs and prevents a return to private visibility; owners can still change the title. Owners can promote unlisted grids to public visibility through the publishing endpoint; publicly listed grids cannot return to unlisted visibility. All mutations check ownership and reject cross-origin browser requests. The server limits API traffic, creation, retries, active workers, and SSE connections. Temporary rate and in-flight spending limits return cells to the pending queue and impose a session-wide cooldown, releasing worker slots while other users continue. One scheduler timer wakes expired cooldowns, and each cell can retry up to five times with exponential backoff, jitter, and Retry-After handling. Permanent billing and authentication failures still pause the session's grids. Worker registries, generation subscriptions, retry counts, cooldowns, and execution credentials live in the inference process; browser connections and HTTP rate counters live in the web process. Each process has its own provider catalog cache; SQLite retains configuration, state, and credentials across process restarts, while the filesystem retains generated outputs.

Manual keys use a separate path alongside OAuth. `src/openrouter-key.ts` stores the key in localStorage and synchronizes connection state across tabs. The shared connector validates it through `POST /api/auth/key`, which checks OpenRouter's key endpoint without persisting the credential. Validation, worker recommendation, Generate, and Resume send the key in an Authorization header; reads and SSE use the existing owner cookie. Manual keys take precedence over an OAuth credential. Selecting OAuth clears the local manual key before the existing redirect, and Disconnect clears it before using the existing session-key removal route.

`server/provider.ts` checks manual-key credits using the account balance and key's remaining limit, choosing the lower available value. When account credits are inaccessible, a finite remaining key limit supplies the concurrency estimate; when neither is available, the recommendation is one. The scheduler retains the supplied key in a private per-grid memory map while work is queued or running, including automatic retries, and drops it when the grid pauses or finishes. Current request closures keep it only until their calls settle. Closing a tab does not stop queued work, while resuming after Pause or a process restart requires the browser to resend it. Manual keys are never written to SQLite, files, billing entries, or grid snapshots. `server/manual-keys.ts` handles bearer-key extraction and connection HTTP responses; it delegates key verification to the provider.

## Accounts and attribution

Users begin with an anonymous session. GitHub authorization uses a provider adapter, S256 PKCE, a session-bound single-use state, and a ten-minute expiry. The callback retrieves the authenticated profile and identifies users by the provider and immutable GitHub numeric ID, refreshing their display username at sign-in. GitHub tokens are discarded after profile retrieval. GitHub client credentials are required at startup. Pending identity authorization is separate from OpenRouter authorization.

Successful sign-in atomically claims the anonymous session's grids and rotates its cookie. Grids retain their anonymous origin and may also have an account owner; account ownership takes precedence for access, mutation, listings, and billing. Signing out rotates the cookie again and removes account access while retaining browser-local OpenRouter state. The stable anonymous identifier survives rotation, and running work retains its initiating browser connection; resuming from another browser uses that browser's connection. Session expiry remains thirty days. SSE rechecks session validity and grid access before sending snapshots and closes invalidated sessions on its heartbeat.

Draft attribution resolves the current account profile. First publication stores a public identity snapshot or Anonymous, and subsequent account changes cannot modify it. Historical published grids without a snapshot remain Anonymous. Public grid snapshots and summaries contain author display data but omit both anonymous and account ownership identifiers. Profile links and grid links are separate anchors in listing rows.

OAuth attempts share return-path, state, and expiry policy. `oauth4webapi` generates PKCE values and validates GitHub authorization-code exchanges; OpenRouter's custom key exchange stays in the provider adapter. Signing in claims persisted anonymous-grid metadata before rotating the browser session. Engine snapshots read current ownership without changing the initiating execution owner.

Grid ownership and publication rules live in `server/grid-policy.ts`. Grid routes share access lookup and apply publication only after policy validation. The client publishing widget owns its TanStack mutation and updates grid and list queries.

Creation and grid retry/pause actions share a TanStack inference mutation hook for request credentials, pending state, failures, and low-balance confirmation. Creation, editing, and successful generation use the same draft-storage helpers.

New grids never select a model from catalog order. Generation requires a deliberate fixed model or model-axis selection; the unused fixed-model field is empty for model-axis grids.

Shared modal, clipboard-button, and format-icon components own their UI lifecycles. Tooltips use one shared hook across creation, grid headers, output cells, and grid lists.

The browser's grid response type is inferred directly from the server presenter, so response fields have one TypeScript definition. Ownership tokens are excluded before constructing the presented object.

Both mock and real-provider browser fixtures mount the application's frontend router, including its HTML and asset caching policy.

`Grid.title` is optional metadata separate from generation input. The owner-authorized `PATCH /api/grids/:id/title` trims titles, accepts at most 40 characters, and clears an empty title. It updates only title metadata and its revision, obtains a fresh engine snapshot, and notifies browser subscribers, and also permits published-grid titles to change without modifying generation inputs or outputs. Grid summaries expose the title, and listings fall back to the prompt. `src/grid/grid-title.tsx` owns inline title editing through TanStack Query, prompt copying, and an interactive Tippy overlay shown only when the prompt is truncated. Titles wrap when space is limited instead of being ellipsized, both in the header and grid listings. The title editor enforces the same 40-character limit as the API. Title colors follow the theme; prompt text shares the wordmark color.

## Thinking traces

`server/inference.ts` reads exposed reasoning text and summaries from raw OpenRouter stream events. This preserves thinking interleaved after answer text, which the installed adapter omits from normalized reasoning deltas. Readable `reasoning_details` take precedence over the duplicate legacy `reasoning` field, and encrypted blocks are omitted. Image responses also retain exposed thinking when present. Capture preserves the selected effort setting and does not request hidden reasoning that the provider does not return. When a text stream ends at its length limit with no non-whitespace output and reported reasoning tokens reaching the requested token limit, the inference adapter raises a specific thinking-exhaustion error after recording completion usage. The normal failure path preserves the trace, records the charge, and presents the error on the cell. Other incomplete responses retain the generic error.

`server/jobs.ts` accepts progress only from the current, non-aborted controller for a cell. It appends thinking to attempt-specific files before publishing the corresponding snapshot. Cancellation blocks late chunks and results, settled callbacks cannot mutate completed or retried cells, and throttled notifications check that their runtime still belongs to the grid. Output drafts and price estimates remain transient; terminal snapshots keep the thinking URL instead of retransmitting its body.

`/outputs/:id/thinking/:attempt` checks the same ownership and publication policy as other output routes and serves plain text only when the attempt matches the cell's current thinking identifier. Attempt-specific query keys prevent an older fetch from replacing newer thinking. Trace files sit outside generated bundles, are absent from downloads, and cannot be served by isolated HTML hosts.

The thinking control uses a brain icon to open raw thinking and a palette icon to return to output. While generation runs, thinking appears automatically until output content is available unless the user explicitly selects a view. Output and thinking previews remain mounted when toggled, preserving frame state and scroll positions. Thinking uses the shared text preview in its wrapped raw mode, which bypasses width measurement and scaling and displays 14px monospace text with preserved newlines, word wrapping, and vertical scrolling. Long unbroken strings wrap within the available width. This mode supports expansion across output formats, streams through grid snapshots, and keeps its last draft visible while the saved trace loads. Completed and failed traces remain available after reload. Wrapped thinking previews follow appended text and resize changes while pinned to the bottom. The preview records its scroll position after automatic scrolling, so queued scroll events and content growth do not suspend following. Upward wheel input or upward movement away from the bottom suspends following; returning within two pixels of the bottom resumes it, including the handoff to the saved trace.

## Independent web and inference lifetimes

`server/index.ts` starts the web process and connects to the separate `server/engine.ts` process. `createApp` requires a `GenerationAPI`; it never creates a scheduler, recovers work, or clears previews. The engine owns provider calls, queued work, fairness, retry timers, cancellation, execution credentials, streaming output and thinking, preview production, and generation billing. Web code owns authentication, account and grid metadata changes, model discovery for forms, presentation, and authorized output delivery.

`server/generation-api.ts` defines the explicit versioned contract. Its operations accept identifiers and named parameters rather than mutable grids or arbitrary method names. `server/generation-server.ts` exposes HTTP over a local Unix socket with owner-only permissions; it has no TCP listener or browser-facing route. `server/generation-client.ts` implements the same typed interface and checks the protocol response header. It uses Node's JSON stream consumer and line reader for response decoding, with an AbortSignal controlling subscription cancellation. The local subscription has no idle timeout or heartbeat; the browser-facing SSE route retains its heartbeat and session checks. Commands validate strict payload schemas. Operational commands are available only through this private socket.

| Operation                  | Contract                                                                                                                                                                                                    |
| -------------------------- | ----------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `POST /v1/grids/start`     | `{ gridId, sessionId, manualKey? }`; rechecks session, ownership, publication, credentials, and admission, then returns the current grid. Starting an already running grid does not create another attempt. |
| `POST /v1/grids/pause`     | `{ gridId, sessionId }`; rechecks ownership, cancels that grid, and returns its state.                                                                                                                      |
| `GET /v1/grids/:id`        | Current metadata combined with canonical live generation state.                                                                                                                                             |
| `GET /v1/grids/:id/events` | Newline-delimited full grid snapshots, beginning with the current snapshot.                                                                                                                                 |
| `POST /v1/previews/path`   | `{ cellId, path }`; resolves only files belonging to that cell's active preview attempt. Web code checks output authorization before calling it.                                                            |
| `GET /v1/status`           | Protocol version, process instance identifier, admission state, running-call count, and active-grid count.                                                                                                  |
| `POST /v1/drain`           | Closes admission for new starts and resumes while accepted grids continue through their queues and retries.                                                                                                 |
| `POST /v1/accept`          | Reopens admission.                                                                                                                                                                                          |

Errors have `{ code, error }` bodies. `DRAINING` and `UNAVAILABLE` use 503, `NOT_FOUND` uses 404, `PUBLISHED` uses 409, `AUTH_REQUIRED` uses 401, and `INVALID_REQUEST` uses 400. Transport failures do not automatically replay commands: a lost start response may represent accepted work. A later snapshot or an explicit Resume reconciles that state without starting duplicate running cells.

Creation inserts immutable configuration and initial cell rows together. After creation, `Store.saveGeneration` writes only status, interruption, and cell state; metadata operations update only title, publication, or ownership. Each mutation allocates a revision in SQLite, including live draft changes, so revisions remain ordered across both processes. Snapshots combine freshly read metadata with live cells. Publication checks and generation admission use immediate transactions to serialize publication against retries. The engine records billing calls; the web process reads them for billing presentation.

Subscriptions register before sending their initial snapshot in the same engine event-loop turn. The web process forwards snapshots through the browser SSE route, discards older revisions, and rechecks current session and persisted ownership before delivery. A web restart disconnects browser streams without cancelling provider calls. EventSource reconnects and receives a fresh snapshot, including drafts, thinking, estimates, and preview identifiers. Slow subscribers are disconnected instead of accumulating unbounded snapshots. Preview files and their in-memory attempt registry survive web replacement.

A soft update replaces web code and frontend assets while leaving the engine and its release files intact. A machinery update drains first and waits for both active-grid and running-call counts to reach zero. Running calls include cancelled requests whose promises have not yet settled. Draining entire accepted grids preserves memory-only manual credentials until their work finishes or pauses. Termination signals also request this drain; a forced process kill still interrupts work. Recovery and preview cleanup run only when starting the engine. Protocol, shared storage, or execution changes require a compatible machinery update.

Runtime validation and crash-boundary coverage are described in [DEVELOPMENT.md](DEVELOPMENT.md#validation).

`src/grid-pan.ts` handles primary mouse drags on the grid scroll container, excluding output content, controls, and resize handles. Pointer capture keeps a drag active across cells and releases it on pointer-up, cancellation, or capture loss. Touch gestures remain in `ZoomableGrid`. `src/contained-image.tsx` centers an image inside a size container and uses its natural aspect ratio with container-relative width and height limits to size the image element itself. Both completed images and streamed SVG previews share this layout, so letterbox padding is outside the image hit area and can start grid panning.
