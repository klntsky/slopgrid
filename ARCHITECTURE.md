# Architecture

`src/main.tsx` mounts the application providers, `src/router.tsx` defines routes, and `src/layout.tsx` owns the navigation shell and grid header portal target. Pages live under `src/pages/`, creation controls and draft persistence under `src/create/`, and shared connection controls and inference dialogs under `src/components/`. Grid query/SSE/action state lives in `src/grid/use-grid.ts`, while the header, output table, and individual output cells have separate components under `src/grid/`. The React client uses TanStack Router for creation, grid history, billing, settings, and grid routes, and TanStack Query for API state. A progressive questionnaire preserves previous answers and stores its in-progress form in sessionStorage across OAuth redirects. Grid pages use EventSource while generation is running or a paused grid still has active requests, receiving server snapshots and draft text while text generation streams. The client closes the connection once the grid is stable and reopens it when an action starts generation again. Stable grids do not open a connection when loaded. SVG drafts are completed locally for a disposable image preview: open elements and quoted attributes are closed, unfinished attribute names are omitted, and trailing partial entities are dropped. The browser decodes each candidate as an image before replacing the last valid preview. These changes never modify the stored final SVG; other text formats show escaped draft text. Persisted revision numbers prevent late HTTP responses from overwriting newer SSE state. Streaming drafts stay in the active worker’s memory without being written to SQLite. SVG and Markdown draft text is included in live snapshots; website snapshots contain only a versioned preview URL rather than the bundle text. Website cells reload their isolated iframe as file snapshots advance, using the existing grid SSE connection. Images and SVG render directly as image elements; HTML previews use sandboxed iframes with scripts allowed. Markdown previews fetch the original Markdown file through the output route’s raw mode and render React elements with `react-markdown` and `remark-gfm`. The parser loads on demand in the browser, and unchanged Markdown content is memoized across grid updates. The shared `shared/markdown.tsx` component also renders direct output pages through React server rendering, so both views use the same parser and URL policy. Raw HTML remains escaped text without HTML parsing plugins or DOM insertion. Links, images, and task lists use the renderer and plugin defaults. Vite selects the entity decoder’s lookup-table implementation rather than its browser implementation that writes to innerHTML. Grid pages render their title, pause/resume control, accessible progress bar, and action buttons into a header slot through a React portal. The progress bar spans the bottom of the header and counts complete and error cells as finished. Visual segments follow cell order, coloring successful outputs with the accent and failed outputs red, while the native progress element exposes the finished count and separate success/failure totals to assistive technology. A moving, pulsing spark appears during generation, with reduced-motion support. The shell fills the viewport and gives the remaining space to the grid scroll container. Small grids stretch their cells to fill that space, while larger grids scroll with sticky column and row headers and an empty corner cell. The row-label column sizes to its rotated contents and padding, while output columns initially retain a minimum width of 340 CSS pixels. Resize handles on column labels’ left edges and row labels’ top edges adjust the output column to the right or row below, switching to explicit table dimensions on the first resize. The heading row and label column have no resize handles. The heading row keeps its natural content height when saved output sizes are restored or changed, while the label column retains its measured automatic width. Only output dimensions are stored per grid in localStorage, with no server persistence. Pointer deltas account for table zoom, and the handles also accept arrow keys. On mobile, navigation moves into an anchored hamburger menu that closes after a link selection, an outside pointer press, Escape, or a route change. Model IDs in row and column labels use clipboard buttons with a success icon and an accessible status message. `src/zoomable-grid.tsx` handles two-finger touch gestures inside the grid at any screen size, scales only the table with CSS zoom from the scale that fits the table within the viewport up to 3×, and adjusts scroll offsets around the fingers’ midpoint. Touch-capable grids, detected through `navigator.maxTouchPoints` or an available coarse pointer, start at the scale that fits their full width, with their base table dimensions fixed before applying zoom. One-finger scrolling stays native. Resizing the viewport reapplies the width fit on touch-capable devices and restores normal scale on devices without touch, and HTML frames retain native pointer input and scrolling; grid gestures can begin on table headings. Markdown previews use native nested scrolling for one-finger gestures, while two-finger touch events bubble to the grid zoom handler. `OutputGrid` can expand one completed Markdown cell into an overlay constrained to the grid workspace, keeping the navigation header visible and the underlying table mounted but hidden and inert. Expansion shares the cached Markdown source, transfers its scroll position, and restores focus to the original expand button on collapse; Escape also closes the overlay. Table zoom, sizing, and scroll offsets remain intact. Theme colors use CSS variables for light and subtly warm dark palettes. A small external bootstrap script applies the saved browser preference before rendering, while a React provider follows system appearance changes, persists explicit overrides in localStorage, synchronizes open tabs, and updates the browser theme color. Generated output canvases retain their own appearance.

`server/app.ts` composes the application dependencies and middleware in request order. Host dispatch and generated HTML isolation live in `server/hosting.ts`; API origin and rate checks live in `server/security.ts`. Cookie/session handling, rate limiting, and grid snapshot presentation have dedicated modules. The private billing router pages inference attempts by session ownership, omits finish reasons from its response, and provides totals for reported charges and unavailable costs. Routers under `server/routes/` handle authentication, model listing, grids, SSE, and same-origin outputs; the inference guard owns the balance check and session concurrency policy. The server entry point serves the built client in production and Vite middleware in development. Grid creation and Resume query OpenRouter credits before starting work. Balances below $3 require explicit continuation, shown through a top-up dialog, and persist a one-worker limit on the browser session. The scheduler applies that limit across its grids alongside fair allocation; each accepted start or resume sets the session limit to `max(1, floor(balanceUsd / 3))`, subject to the shared worker cap. `server/domain.ts` validates grid inputs, expands their Cartesian product, substitutes prompt variables literally, and validates generated static bundles. `server/provider.ts` owns the model catalogs and credit checks, and delegates generation to `server/inference.ts`, which makes one streamed text call through the AI SDK OpenRouter provider or generates images through the provider's image API. `server/billing.ts` owns durable inference-call recording and session-filtered history queries. It reads per-model reasoning metadata, distinguishing explicit effort lists, unrestricted effort selection, unavailable selection, mandatory reasoning, and unpublished router capabilities. `server/http.ts` supplies the shared upstream HTTP transport with connection, header, and body timeouts disabled. Catalog discovery, credit balance checks, OAuth exchange, and inference use this transport, and inference abort signals carry user cancellation without deadlines or application output-byte limits. `server/generation-budget.ts` converts the per-cell dollar allowance into an explicit text output-token ceiling using catalog pricing, a conservative input estimate, and model/context ceilings. Budget configuration lives once in the grid input and is derived into cells when expanding a grid. Inference applies matching provider-price routing constraints and gives the cell call its full allowance; retries start a fresh allowance. Images retain their dedicated API path without a text-token budget. `server/partial-website.ts` decodes file names and JSON string contents incrementally, including unfinished values and escapes split across chunks. `server/website-previews.ts` writes changed files atomically into temporary attempt directories, refreshes each bundle at most once per 750 ms, and clears temporary files on cancellation, retries, and completion. The entry point explicitly clears leftover previews at startup. Preview metadata remains in memory, and preview notifications are coalesced per grid through the scheduler’s 300 ms draft throttle. HTML hosts serve both relative preview assets and completed bundles, while the application host serves no generated HTML. `server/failures.ts` extracts provider error messages, codes, retry delays, and transient-limit classification from HTTP and streamed errors. Cell state persists the message and code; a waiting-to-retry flag stays in memory. `server/model-resolution.ts` resolves catalog `alias_target.slug` chains before a grid is expanded or saved. The saved configuration contains only concrete model IDs, with duplicate model-axis targets collapsed; retries and Edit/Fork therefore reuse the pinned selection. Cyclic aliases and latest aliases without a concrete target are rejected. `canonical_slug` differences are not treated as alias markers. `server/compatibility.ts` classifies thinking effort support as supported, unsupported, or unknown. `src/create/compatibility-table.tsx` shows a compact matrix of selected models and efforts, including fixed selections, with SVG checkmarks only for supported combinations. Model default omits reasoning configuration, None sends `reasoning.enabled: false`, and explicit levels send `reasoning.effort` with required-parameter routing. The compatibility table does not block creation, retries, or provider calls; selected settings are sent to OpenRouter, and upstream rejections become cell errors. The inference fetch wrapper creates a durable billing entry before each actual upstream request. Completion metadata stays exclusively in the billing ledger and is omitted from grid snapshots. Each cell’s usage is read directly from its latest inference call without attempt grouping or summation. Entries retain the call phase, status, timestamps, available generation ID and HTTP status, normalized and raw finish reasons, reasoning-token counts, token usage, cost, and failure message/code. Retries create new entries. Cancellation is recorded even when the scheduler discards the partial result. No prompts, outputs, credentials, or headers are stored in the ledger. Startup marks unfinished entries interrupted without sending replacement requests. Non-successful text finish reasons fail the cell while preserving its reported usage, without exposing finish metadata in the interface. Reported USD costs are stored in the inference ledger with token usage. Text costs come from provider metadata; a scoped fetch wrapper preserves image response costs because the installed image adapter drops that field. Missing charges remain unknown rather than being treated as zero, and costs cover reported completed calls in the current attempt, including calls with an unsuccessful finish reason; unreported charges and previous retry attempts are not included.

`server/store.ts` stores grid configuration, sessions, and cell state in SQLite with WAL enabled and foreign keys enforced. Grid configuration is stored once, and cell rows contain status, error, and image media type; usage for recorded calls is derived from the latest ledger entry, and finish metadata stays in the ledger; per-cell prompts and model settings are reconstructed from that configuration. The cell ID and position live in relational columns rather than duplicated JSON. Output-host lookups join a cell primary key to its grid rather than scanning grids or maintaining a second output index. `server/routes/outputs.ts` serves completed output downloads on the application origin with attachment filenames built from the saved grid prompt, grid ID, and axis values. Website downloads use `fflate` to generate ZIP archives asynchronously from stored files, preserving relative paths. SVG, Markdown, and image downloads return their original files. Cell clipboard controls copy text source or PNG image data, converting other image formats to PNG for clipboard compatibility. `server/files.ts` stores each output in a directory keyed by its cell ID: text files keep their relative paths, and images are raw binary files. A complete bundle is staged in a temporary directory and renamed into place before the cell is marked complete; interrupted writes cannot expose a partial bundle. A retry replaces any files left by a crash before completion was saved. Generated file bodies are never stored in SQLite or grid snapshots. Completed files are not rewritten when grid state changes.

`server/migrations.ts` defines ordered SQL migrations with positive, strictly increasing versions. Startup validates the sequence and rejects unsupported database versions, then applies each pending migration and its SQLite `user_version` update in one immediate transaction. Failed migrations roll back both SQL changes and version updates. There is no legacy schema conversion. Each session owns grids through an opaque cookie token. OpenRouter PKCE verifiers and state are server-side; the callback checks state and a ten-minute deadline before exchanging the code. The resulting key is encrypted using AES-256-GCM. Neither keys nor ownership tokens appear in API grid responses.

`server/jobs.ts` schedules cells across all active grids using a shared worker pool. The configured maximum defaults to 100. Each available slot goes to a browser-session owner with the fewest active cells, with ties resolved by allocation history. Capacity is never reserved, and fair allocation never cancels active calls. Completed cells are skipped on every resume or retry. A manual pause aborts that grid’s active requests, discards partial drafts, and stops queued cells. Canceled attempts keep their slots until they settle, and late chunks or results are ignored; resuming cannot start the same cell twice. Billing and authentication failures pause queued work across the owner’s active grids without aborting its other in-flight calls. Other failures mark the affected cell as retryable. Parallel cells mutate one canonical grid object, so retries during in-flight work preserve completed results. State updates are persisted before SSE notification, while temporary draft notifications are throttled per grid. The server entry point explicitly calls `recoverInterruptedGrids` once at startup to mark running grids paused and interrupted cells pending; opening a `Store` does not change generation state. Generation resumes only through an owner-authorized retry. Publishing requires every cell to be complete or failed and freezes further retries.

Each cell receives a random 192-bit output identifier. HTML bundles use a separate hostname formed from that identifier and an environment-configured suffix beginning with a hyphen. Host matching accepts only the configured single-label pattern and exact cell identifier. The iframe CSP uses a whole-label wildcard for the HTML hosts’ parent domain, since CSP does not support partial-label wildcards. Host dispatch runs before JSON parsing, session cookies, API routes, or frontend serving. HTML hosts serve only that bundle's validated files, and `/api` cannot reach application handlers there. Their CSP sandbox omits `allow-same-origin` while allowing scripts and static assets; connections, forms, and cookie access are blocked, including when opened in a separate tab.

Images, SVG, and Markdown use `/outputs/:id` on the application host. Images are served as image bytes rather than HTML wrappers. SVG is served as `image/svg+xml` and previewed through an image element, which disables scripts and external resources. Direct visits to the SVG output URL retain the restrictive response CSP. Markdown is rendered with raw HTML escaped. These responses bypass session middleware, set no cookies, and have a CSP sandbox without script permission. The application cookie remains host-only and uses the `__Host-` prefix under HTTPS. HTML bundles cannot be fetched through the application output route, and the HTML host handler serves no other output formats.

Unpublished grids require their owning account or anonymous browser session for API access. Output URLs themselves are bearer capabilities and are readable without that cookie; random identifiers make their URLs unguessable. Publishing requires every cell to be complete or failed; pending and running cells prevent publication. Published grids are readable by anyone with the grid link, including failed cells, and retain the original owner for display controls. Visibility distinguishes private grids, unlisted published grids, and publicly listed grids. Only publicly listed grids appear in the public summary endpoint, which omits owner and cell data. Publishing permanently locks contents and prevents a return to private visibility. Owners can promote unlisted grids to public visibility through the publishing endpoint; publicly listed grids cannot return to unlisted visibility. Existing published grids migrate to unlisted visibility. All mutations check ownership and reject cross-origin browser requests. The server limits API traffic, creation, retries, active workers, and SSE connections. Temporary rate and in-flight spending limits return cells to the pending queue and impose a session-wide cooldown, releasing worker slots while other users continue. One scheduler timer wakes expired cooldowns, and each cell can retry up to five times with exponential backoff, jitter, and Retry-After handling. Permanent billing and authentication failures still pause the session’s grids. Worker registries, listeners, retry counts, cooldowns, rate counters, and model caches live in one process; SQLite retains configuration, state, and credentials across process restarts, while the filesystem retains generated outputs.

Manual keys use a separate path alongside OAuth. `src/openrouter-key.ts` stores the key in localStorage and synchronizes connection state across tabs. The shared connector validates it through `POST /api/auth/key`, which checks OpenRouter’s key endpoint without persisting the credential. Only validation, Generate, and Resume send the key in an Authorization header; reads and SSE use the existing owner cookie. Manual keys take precedence over an OAuth credential. Selecting OAuth clears the local manual key before the existing redirect, and Disconnect clears it before using the existing session-key removal route.

`server/manual-keys.ts` checks manual-key credits using the account balance and key’s remaining limit, choosing the lower available value. When account credits are inaccessible, a finite remaining key limit supplies the concurrency estimate; when neither is available, concurrency is one. The scheduler retains the supplied key in a private per-grid memory map while work is queued or running, including automatic retries, and drops it when the grid pauses or finishes. Current request closures keep it only until their calls settle. Closing a tab does not stop queued work, while resuming after Pause or a process restart requires the browser to resend it. Manual keys are never written to SQLite, files, billing entries, or grid snapshots. OAuth PKCE, encrypted credentials, and OAuth credit checks retain their existing behavior.

## Accounts and attribution

Users begin with an anonymous session. GitHub authorization uses a provider adapter, S256 PKCE, a session-bound single-use state, and a ten-minute expiry. The callback retrieves the authenticated profile and identifies users by the provider and immutable GitHub numeric ID, refreshing their display username at sign-in. GitHub tokens are discarded after profile retrieval. GitHub client credentials are required at startup. Pending identity authorization is separate from OpenRouter authorization.

Successful sign-in atomically claims the anonymous session’s grids and rotates its cookie. Grids retain their anonymous origin and may also have an account owner; account ownership takes precedence for access, mutation, listings, and billing. Signing out rotates the cookie again and removes account access while retaining browser-local OpenRouter state. The stable anonymous identifier survives rotation, and running work retains its initiating browser connection; resuming from another browser uses that browser’s connection. Session expiry remains thirty days. SSE rechecks session validity and grid access before sending snapshots and closes invalidated sessions on its heartbeat.

Draft attribution resolves the current account profile. First publication stores a public identity snapshot or Anonymous, and subsequent account changes cannot modify it. Historical published grids without a snapshot remain Anonymous. Public grid snapshots and summaries contain author display data but omit both anonymous and account ownership identifiers. Profile links and grid links are separate anchors in listing rows.
