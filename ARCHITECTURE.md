# Architecture

The React client uses TanStack Router for creation, grid history, settings, and grid routes, and TanStack Query for API state. A progressive questionnaire preserves previous answers and stores its in-progress form in sessionStorage across OAuth redirects. Grid pages use EventSource while generation is running or a paused grid still has active requests, receiving server snapshots and draft text while text generation streams. The client closes the connection once the grid is stable and reopens it when an action starts generation again. Stable grids do not open a connection when loaded. SVG drafts are completed locally for a disposable image preview: open elements and quoted attributes are closed, unfinished attribute names are omitted, and trailing partial entities are dropped. The browser decodes each candidate as an image before replacing the last valid preview. These changes never modify the stored final SVG; other text formats show escaped draft text. Persisted revision numbers prevent late HTTP responses from overwriting newer SSE state. Streaming drafts stay in the active worker’s memory and are included in both live notifications and snapshots for a running grid, without being written to SQLite. Images and SVG render directly as image elements; HTML and Markdown previews use sandboxed iframes. Only HTML previews allow scripts. Grid pages render their title, pause/resume control, accessible progress bar, and action buttons into a header slot through a React portal. The progress bar spans the bottom of the header and counts complete and error cells as finished. Visual segments follow cell order, coloring successful outputs with the accent and failed outputs red, while the native progress element exposes the finished count and separate success/failure totals to assistive technology. A moving, pulsing spark appears during generation, with reduced-motion support. The shell fills the viewport and gives the remaining space to the grid scroll container. Small grids stretch their cells to fill that space, while larger grids scroll with sticky column and row headers and an empty corner cell. The row-label column sizes to its rotated contents and padding, while output columns initially retain a minimum width of 340 CSS pixels. Header-edge resize handles adjust column widths and row heights, switching to explicit table dimensions on the first resize. Dimensions are stored per grid in localStorage, with no server persistence. Pointer deltas account for table zoom, and the handles also accept arrow keys. On mobile, navigation moves into an anchored hamburger menu that closes after a link selection, an outside pointer press, Escape, or a route change. Model IDs in output cells and model legends use clipboard buttons with a success icon and an accessible status message. `src/zoomable-grid.tsx` handles two-finger touch gestures inside the mobile grid, scales only the table with CSS zoom from the scale that fits the table within the viewport up to 3×, and adjusts scroll offsets around the fingers’ midpoint. Mobile grids start at the scale that fits their full width, with their base table dimensions fixed before applying zoom. One-finger scrolling stays native. Resizing the viewport reapplies the width fit on mobile and restores normal scale on desktop, and embedded frames ignore pointer input on mobile so gestures reach the parent grid; their full outputs remain interactive through the output link. Theme colors use CSS variables for light and subtly warm dark palettes. A small external bootstrap script applies the saved browser preference before rendering, while a React provider follows system appearance changes, persists explicit overrides in localStorage, synchronizes open tabs, and updates the browser theme color. Generated output canvases retain their own appearance.

The Express server serves the built client in production and Vite middleware in development. `server/domain.ts` validates grid inputs, expands their Cartesian product, substitutes prompt variables literally, and validates generated static bundles. `server/provider.ts` combines the OpenRouter text and dedicated image-model catalogs, streams text through the AI SDK OpenRouter provider, optionally reviews a draft in a second AI SDK call, and generates images through the provider's image API. It reads per-model reasoning metadata, distinguishing explicit effort lists, unrestricted effort selection, unavailable selection, mandatory reasoning, and unpublished router capabilities. `server/http.ts` supplies the shared upstream HTTP transport with connection, header, and body timeouts disabled. Catalog discovery, OAuth exchange, and inference use this transport, and inference abort signals carry user cancellation and output-size enforcement without deadlines. `server/failures.ts` extracts provider error messages, codes, retry delays, and transient-limit classification from HTTP and streamed errors. Cell metadata persists the message and code; a waiting-to-retry flag stays in memory. `server/model-resolution.ts` resolves catalog `alias_target.slug` chains before a grid is expanded or saved. The saved configuration contains only concrete model IDs, with duplicate model-axis targets collapsed; retries and Edit/Fork therefore reuse the pinned selection. Cyclic aliases and latest aliases without a concrete target are rejected. `canonical_slug` differences are not treated as alias markers. `server/compatibility.ts` checks every model/effort combination for advisory warnings in the form; identical warnings are deduplicated across prompt-variable cells. Model default omits reasoning configuration, None sends `reasoning.enabled: false`, and explicit levels send `reasoning.effort` with required-parameter routing. Compatibility warnings do not block creation, retries, or provider calls; selected settings are sent to OpenRouter, and upstream rejections become cell errors. Reported USD costs are stored with each cell's token usage and summed across draft and review only when both charges are available. Text costs come from provider metadata; a scoped fetch wrapper preserves image response costs because the installed image adapter drops that field. Missing charges remain unknown rather than being treated as zero, and costs cover the successful attempt rather than aborted or failed requests.

`server/store.ts` stores grid configuration, sessions, and cell state in SQLite with WAL enabled and foreign keys enforced. Grid configuration is stored once, and cell rows contain only status, error, usage, and image media type; per-cell prompts and model settings are reconstructed from that configuration. The cell ID and position live in relational columns rather than duplicated JSON. Output-host lookups join a cell primary key to its grid rather than scanning grids or maintaining a second output index. `server/files.ts` stores each output in a directory keyed by its cell ID: text files keep their relative paths, and images are raw binary files. A complete bundle is staged in a temporary directory and renamed into place before the cell is marked complete; interrupted writes cannot expose a partial bundle. A retry replaces any files left by a crash before completion was saved. Generated file bodies are never stored in SQLite or grid snapshots. Completed files are not rewritten when grid state changes.

`server/migrations.ts` defines ordered SQL migrations with positive, strictly increasing versions. Startup validates the sequence and rejects unsupported database versions, then applies each pending migration and its SQLite `user_version` update in one immediate transaction. Failed migrations roll back both SQL changes and version updates. There is no legacy schema conversion. Each session owns grids through an opaque cookie token. OpenRouter PKCE verifiers and state are server-side; the callback checks state and a ten-minute deadline before exchanging the code. The resulting key is encrypted using AES-256-GCM. Neither keys nor ownership tokens appear in API grid responses.

`server/jobs.ts` schedules cells across all active grids using a shared worker pool. The configured maximum defaults to 100. Each available slot goes to a browser-session owner with the fewest active cells, with ties resolved by allocation history. Capacity is never reserved, and fair allocation never cancels active calls. Completed cells are skipped on every resume or retry. A manual pause aborts that grid’s active requests, discards partial drafts, and stops queued cells. Canceled attempts keep their slots until they settle, and late chunks or results are ignored; resuming cannot start the same cell twice. Billing and authentication failures pause queued work across the owner’s active grids without aborting its other in-flight calls. Other failures mark the affected cell as retryable. Parallel cells mutate one canonical grid object, so retries during in-flight work preserve completed results. State updates are persisted before SSE notification, while temporary draft notifications are throttled per grid. A restart marks running grids paused and interrupted cells pending. Generation resumes only through an owner-authorized retry. Publishing requires every cell to be complete and freezes further retries.

Each cell receives a random 192-bit output identifier. HTML bundles use a separate hostname formed from that identifier and an environment-configured suffix beginning with a hyphen. Host matching accepts only the configured single-label pattern and exact cell identifier. The iframe CSP uses a whole-label wildcard for the HTML hosts’ parent domain, since CSP does not support partial-label wildcards. Host dispatch runs before JSON parsing, session cookies, API routes, or frontend serving. HTML hosts serve only that bundle's validated files, and `/api` cannot reach application handlers there. Their CSP sandbox omits `allow-same-origin` while allowing scripts and static assets; connections, forms, and cookie access are blocked, including when opened in a separate tab.

Images, SVG, and Markdown use `/outputs/:id` on the application host. Images are served as image bytes rather than HTML wrappers. SVG is served as `image/svg+xml` and previewed through an image element, which disables scripts and external resources. Direct visits to the SVG output URL retain the restrictive response CSP. Markdown is rendered with raw HTML escaped. These responses bypass session middleware, set no cookies, and have a CSP sandbox without script permission. The application cookie remains host-only and uses the `__Host-` prefix under HTTPS. HTML bundles cannot be fetched through the application output route, and the HTML host handler serves no other output formats.

Unpublished grids require their owner session for API access. Output URLs themselves are bearer capabilities and are readable without that cookie; random identifiers make their URLs unguessable. Publishing requires every cell to be complete or failed; pending and running cells prevent publication. Published grids are publicly readable, including failed cells, and retain the original owner for display controls. All mutations check ownership and reject cross-origin browser requests. The server limits API traffic, creation, retries, active workers, and SSE connections. Temporary rate and in-flight spending limits return cells to the pending queue and impose a session-wide cooldown, releasing worker slots while other users continue. One scheduler timer wakes expired cooldowns, and each cell can retry up to five times with exponential backoff, jitter, and Retry-After handling. Permanent billing and authentication failures still pause the session’s grids. Worker registries, listeners, retry counts, cooldowns, rate counters, and model caches live in one process; SQLite retains configuration, state, and credentials across process restarts, while the filesystem retains generated outputs.
