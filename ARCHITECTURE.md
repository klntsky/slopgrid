# Architecture

The React client uses TanStack Router for creation, settings, and grid routes, and TanStack Query for API state. A progressive questionnaire preserves previous answers and stores its in-progress form in sessionStorage across OAuth redirects. Grid pages use EventSource to receive server snapshots, including escaped draft text while text generation streams. Persisted revision numbers prevent late HTTP responses from overwriting newer SSE state. Outputs are displayed in sandboxed iframes. A scroll container with sticky table headers anchors the top row, left column, and corner independently.

The Express server serves the built client in production and Vite middleware in development. `server/domain.ts` validates grid inputs, expands their Cartesian product, substitutes prompt variables literally, and validates generated static bundles. `server/provider.ts` combines the OpenRouter text and dedicated image-model catalogs, streams text through the AI SDK OpenRouter provider, optionally reviews a draft in a second AI SDK call, and generates images through the provider's image API.

`server/store.ts` stores grid snapshots, sessions, and immutable output records in SQLite with WAL enabled. Output-host lookups use a primary-key query rather than scanning grids. Each session owns grids through an opaque cookie token. OpenRouter PKCE verifiers and state are server-side; the callback checks state and a ten-minute deadline before exchanging the code. The resulting key is encrypted using AES-256-GCM. Neither keys nor ownership tokens appear in API grid responses.

`server/jobs.ts` runs one cell at a time per grid. Updates are persisted before SSE notification. Completed cells are skipped on every retry. HTTP or streamed 402 errors pause the grid for billing, 401/403 errors pause it for reconnection, and other failures mark the cell as retryable. A restart marks running grids paused and interrupted cells pending. Generation resumes only through an owner-authorized retry. Publishing requires every cell to be complete and freezes further retries.

Each cell receives a random 192-bit output-host identifier. Host dispatch runs before JSON parsing, session cookies, API routes, or frontend serving. Output requests can access only that cell's validated files; `/api` on an output host cannot reach application handlers. Generated documents receive a CSP sandbox without `allow-same-origin`, preventing cookie access even in a separate tab. Generated code can run scripts and load its own static resources but cannot make connections, submit forms, or navigate through a base URL. The application cookie is host-only and uses the `__Host-` prefix under HTTPS to prevent parent-domain cookie shadowing.

Unpublished grids require their owner session for API access. Output URLs themselves are bearer capabilities and are readable without that cookie; their random host names isolate every cell. Published grids are publicly readable and retain the original owner for display controls. All mutations check ownership and reject cross-origin browser requests. The server limits API traffic, creation, retries, active workers, and SSE connections. Worker registries, listeners, rate counters, and model caches live in one process; SQLite retains results and credentials across process restarts.
